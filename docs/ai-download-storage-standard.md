# AI 下载文件统一存储规范

## 1. 目的与范围

本规范用于管理 AI-worker 中由 AI 从网络或外部系统下载、获取的普通文件，使文件可定位、可校验、可追溯，并避免散落到桌面、系统下载目录、源码仓库、OpenClaw workspace 或运行时临时目录。

默认生产节点的统一根目录为：

```text
/Users/Shared/aiworker-storage/ai-downloads/
```

本规范只约束后续下载，不自动迁移、覆盖或删除历史文件。

## 2. 目录结构

```text
/Users/Shared/aiworker-storage/ai-downloads/
└── <project-slug>/
    └── YYYY/MM/DD/
        └── <task-slug>/
            ├── _incoming/
            ├── files/
            └── manifest.json
```

- `project-slug` 与 `task-slug` 只使用小写英文、数字和连字符，并表达真实项目与任务用途。
- `_incoming/` 只存放未完成、待校验或可安全重试的文件。
- `files/` 只存放已完成字节数、格式和 SHA-256 校验的文件。
- `manifest.json` 保存任务级下载清单；任务目录默认使用 `0700`，清单默认使用 `0600`。后续多人共享前必须另行建立用户组、权限和审计方案。

## 3. 下载流程

1. 下载前确认项目、任务、用途、来源合规性、预计大小和目标卷剩余空间。
2. 先在对应任务的 `_incoming/` 中写入临时文件，不直接写入 `files/`。
3. 下载完成后校验文件字节数、可读格式和 SHA-256；媒体文件还应执行轻量可读性探测。
4. 校验通过后将文件原子转入 `files/`，并把状态写为 `verified`；失败文件保留为可诊断状态，不伪装成成功。
5. 任务完成后更新清单；后续归档或删除必须依据清单精确定位，不使用宽泛路径、通配符或未解析变量作为删除目标。

## 4. 清单字段与脱敏

每个文件至少记录以下字段：

```json
{
  "projectSlug": "example-project",
  "taskSlug": "reference-download",
  "downloadedAt": "2026-08-07T00:00:00Z",
  "sourceHost": "example.org",
  "originalName": "reference.bin",
  "storedName": "reference.bin",
  "bytes": 0,
  "sha256": "",
  "purpose": "task input",
  "status": "verified"
}
```

默认只保存来源域名，不保存查询参数、片段、Cookie、Token、签名 URL 或其他凭据。确需保留完整来源时，应写入仓库外的受控记录，并先确认其不含秘密。

## 5. 专用目录例外

以下资产继续使用各自专用目录，不混入普通下载根目录：

- 模型权重与模型缓存；
- 应用、n8n、索引或任务数据库；
- 生产备份、迁移归档和事故快照；
- 密钥、证书、OAuth 状态和其他凭据；
- 构建缓存、运行缓存和临时输出；
- 视频分析链的 0700 受控收件箱与任务工作目录。

视频运行时收件箱只承担短期传输和任务隔离，不能替代长期下载归档。任何新增例外都必须在项目规范中注明用途、目录、权限、保留策略和 Git 边界。

## 6. Git 与生命周期边界

- 下载文件、模型权重、媒体、数据库、缓存和运行时清单默认不进入 Git。
- 包含本机绝对路径、敏感来源或未脱敏元数据的 `manifest.json` 不进入 Git。
- GitHub 只管理本规范、无密钥清单模板、可复现管理脚本和脱敏运维记录。
- 不自动整理历史目录。历史迁移前应先只读盘点、确认归属与重复项、建立可验证备份，再以独立任务执行和验收。
- 统一下载目录不是缓存，不设默认 TTL 或自动清理周期；文件保留、归档和删除必须由任务级策略或用户确认决定。
- 删除必须精确到已经核验的目标；原片、数据库、索引、模型权重、备份和既有收件项不得因目录整理被顺带删除。
