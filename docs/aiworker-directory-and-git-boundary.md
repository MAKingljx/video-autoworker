# AI-worker 目录与 Git 边界

AI-worker 根是 `PROJ-VIDEO-AUTOWORKER` 的项目管理根与 Git 根，使用同一个 `MAKingljx/video-autoworker` 仓库。产品物理路径保持 `video-autoworker/`，内部 `src/` 为业务源码；构建与测试从产品目录执行。

## 目录职责

| 路径 | 职责与 Git 边界 |
|---|---|
| `.github/workflows/` | 根级 CI，明确使用产品工作目录 |
| `AGENTS.md`、`README.md` | 公共项目协作规则与入口 |
| `video-autoworker/` | 产品源码、工作流、测试、部署脚本、配置模板和脱敏运维记录 |
| `docs/`、`scripts/`、`launch-agents/` | 经审查的公共管理资料、辅助脚本及无密钥模板 |
| `repositories/video-autoworker.git/` | 本机根工作树共享的 Git 对象存储，排除上传，不能当缓存删除 |
| `rollback/`、`tmp/` | 按任务临时重建和验证，排除上传，任务结束后核对退役 |
| `private/`、`memory/`、`output/` | 私有资产、原始记录和生成结果，保留本机 |

身份标记保持私有权限，不进入 Git、上传、压缩包、镜像或发布制品。本机连接信息、长期私有记忆、OpenClaw 工作区身份与状态文件、依赖、缓存、数据库、索引、模型和密钥均继续排除。可共享结论进入正式运维记录。

## 源码恢复

Git 提交历史完整保留，不以“保留两份备份”为理由截断历史。常规更新使用 Git 增量同步，不再每次制作整仓备份或保留一套完整回滚源码。重建历史提交时使用独立临时工作树，按该提交的布局识别产品路径：旧提交可能是 flat，新提交位于 `video-autoworker/`。不得在当前工作区直接覆盖历史目录布局。

任务结束后先确认提交有持久引用、源码没有独有修改、忽略数据已核清、相关进程已退出，再通过 Git 正常退役临时树。尚被安装或进程引用的目录保留并记录解除条件。

## 构建与部署

Git 根和产品根是不同概念，统一由 `video-autoworker/scripts/lib/git-source-layout.mjs` 解析。生产源校验覆盖整个 Git 根的干净状态，文件摘要通过对应提交的正确路径读取。Shell 发布入口先验证共享路径模块本身，再调用其功能。

CI 按改动范围选择检查：文档不跑安装恢复；普通功能使用相关测试和需要的构建/界面验收；核心运行、安全、状态、依赖、发布框架或影响不明时执行完整验证。选中的重测试使用独立环境并行，最终检查要求每一项选中任务成功。

制品可在独立暂存中复用已验证成员、只传输差异；目标仍核对完整成员、依赖闭包、摘要和启动。先完成构建、检查和真实隔离验收，再进入生产维护窗口。备份、切换及实际进程/数据库/业务验收完成后恢复接单；失败优先恢复原服务。

## 运行资产恢复

数据库、素材、索引、实际运行配置和密钥由各自恢复机制保护，Git 不代替这些备份。每个恢复对象在当前副本之外最多保留两个已校验历史版本；先验证新的恢复点，再清理超额历史，不删除源数据或唯一可用恢复点。当前线上恢复需要的不可变发布制品也按实际引用和兼容性管理。

历史清理的私有精确清单继续保留在本机受控记录中，旧的一次性清理脚本不作为日常工具重放。公共文档不包含原始数据、凭据、会话内容或私有恢复包。
