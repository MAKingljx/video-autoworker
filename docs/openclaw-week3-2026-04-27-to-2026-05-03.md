## 2. 命令

以下命令可作为第三周阶段的常用操作入口，适合写入周报或后续运维手册：

```bash
# 连接远端主机
ssh heisenberg

# 查看远端 OpenClaw 版本
ssh heisenberg 'openclaw --version'

# 查看远端 OpenClaw 与 Gateway 状态
ssh heisenberg 'openclaw status'

# 检查插件健康状态
ssh heisenberg 'openclaw plugins doctor'

# 查看当前可用搜索 provider
ssh heisenberg 'openclaw infer web providers'

# 测试 DuckDuckGo 搜索链路
ssh heisenberg 'openclaw infer web search --provider duckduckgo --query "今日 人工智能 新闻"'

# 检查本地 Ollama 模型
ssh heisenberg 'ollama list'

# 验证 browser 插件帮助信息
ssh heisenberg 'openclaw browser --help'
```

如果后续需要把命令整理得更偏“值班手册”风格，可以进一步拆成“连接类命令、排障类命令、模型类命令、搜索类命令”四组。

## 3. 使用建议

第三周之后，建议在日常使用中固定几个基本原则。第一，统一通过 `ssh heisenberg` 进入远端环境，避免多人继续混用旧别名，减少文档、脚本和命令记录不一致的问题。第二，当前最稳定的默认组合仍应是“云端主模型 + 本地 embedding”，也就是保留 `openai-codex/gpt-5.5` 作为主推理模型，同时继续使用本地 `ollama/nomic-embed-text` 承担记忆嵌入，这样可以兼顾能力和成本。

第三，搜索链路暂时不要把 DuckDuckGo 当成稳定生产能力。虽然配置侧已经可用，但真实测试表明当前出口 IP 会触发挑战页，因此更适合把它视为实验能力，而不是正式依赖。若后续仍坚持免额外 API 路线，建议优先评估自建 `SearXNG`，或者走已登录态浏览器自动化搜索。第四，涉及 Gateway 启动时，如果远端 workspace 仍放在 `~/Documents/...`，要继续警惕 macOS 的 TCC/EPERM 限制；在这种情况下，前台运行 Gateway 往往比后台 `LaunchAgent` 更稳。

最后，建议把“配置改动同步文档”作为固定动作：凡是新增节点、调整插件 allowlist、修改模型路由或改变公网入口，都同步更新 `TOOLS.md`、`MEMORY.md` 和当天 `memory/YYYY-MM-DD.md`，这样后续多人协作时，环境才不会再次回到“能跑但说不清”的状态。
