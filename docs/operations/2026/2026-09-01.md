## 本地候选加固

- 兼容 macOS `launchctl print-disabled` 的 `enabled/disabled` 与历史 `true/false` 两种输出。
- runtime guard 只允许一个已知旧工具 SHA 恢复 rename 前中断 intent；receipt/status 不接受旧工具摘要。
- 权威 Mission Control 与 n8n SQLite 采用来源进程数字 FD、guard verifier FD、better-sqlite3 新连接数字 FD 三层 path/device/inode 绑定，并在查询后和 close 前复核。
- receipt anchor 与 restore anchor 分别作为正向隔离和恢复的唯一提交点；rename 后普通失败不再自动反向移动或启 lane。
- 新增 `--hold-guardian yes`：输出 `prepared-held` 后保持同一 guardian 进程、inode 与 token 每 5 秒刷新，持续覆盖 orphan dry-run 和备份 prepare。
- guardian 正文只在创建时写入并 fsync，后续只用 `futimes` 刷新同一 inode 的 mtime；实际 holder 由独立 owner sidecar 标识，接管通过同卷私有 attempt 目录原子替换并同步两个父目录。marker、owner 或 pending 任一步被 SIGKILL 后都只能按不可变 intent/receipt 精确收敛，不覆盖唯一 marker，也不在 batch root 遗留临时成员。
- restore 改为不可变 restore intent 驱动的追加式续作；在反向 rename、guardian 交接、lane active、receipt 与 anchor 各阶段被 SIGKILL 后均可幂等收敛。
