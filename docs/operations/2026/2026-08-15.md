# 2026-08-15 AI-worker 0.5 视频学习发布候选

## 状态

本记录描述经过本地验证、等待受控部署的 `0.5.0` 候选。它不是 GitHub main
已发布、远端已安装或生产验收完成的证据。生产事实只在部署成功后的追加记录中陈述。

## 目标与边界

候选支持：千问在已授权的 Telegram 私聊中识别一个绝对视频文件或目录；单视频和
目录批次进入同一持久化全局串行 video lane；用户在后续消息中提供完整 `taskId` 或
`batchId` 时只读一次正式状态接口。

本次发布范围限于 Git 管理的插件、`aiworker-task-flow` skill、LaunchAgent 模板和
无密钥安装脚本。发布流程不得创建视频任务、n8n execution、媒体文件、SQLite 记录或
修改 Mission Control/n8n 服务。

## 设计与防护

- `before_dispatch` 是唯一对话入口。它只为候选视频请求调用一次无工具 Qwen
  分类；鉴权、原始消息路径/ID 证据、稳定 ID 和 runner 副作用仍由宿主控制。
- 目录派发按确定性清单写入批次状态；所有视频共享进程级全局锁。LaunchAgent 在登录
  与异常退出后恢复扫描未终态批次，不会为同一批次并行派发多个视频。
- 插件先以 `releaseReady=false` 安装。关闭时不调用 classifier、runner 或状态客户端。
  只有独立激活器同时确认 canonical SHA、候选配置、hook-only runtime、Gateway RPC、
  lane dry-run 和受保护监听未漂移后，才写入 `releaseReady=true` 并刷新
  `qwen-current`。
- 插件和 lane 安装器都验证恢复点；每个受管备份集合最多保留两份已验证恢复点。任何
  安装或激活失败都保持或恢复关闭闸门，且不删除任务状态或媒体。

使用 Node `22.22.3` 完成：

- 根 Vitest：`102` 个测试文件、`1047/1047` 通过；其中 task-flow `25` 项、lane
  supervisor `6` 项通过。
- 插件 Vitest：`24` 个测试文件、`306/306` 通过。
- TypeScript `--noEmit`、所有发布 shell/Node 脚本语法检查和 `git diff --check` 通过。

这些是本地候选证据，不能替代远端安装检查、真实 Telegram 入站或真实视频任务验收。

## 受控发布与回滚

同一已批准 SHA 的顺序为：

1. `upgrade-aiworker-video-command-status-plugin.sh --apply` 安装关闭的插件闸门。
2. `install-aiworker-task-flow-skill.sh --apply` 安装 skill 和受控工作区规则。
3. `install-aiworker-video-lane-supervisor.sh --apply` 安装并验证常驻 lane。
4. `activate-aiworker-video-learning-release.sh --apply` 打开闸门。

前三步不会允许 `0.5.0` 派发。若任一步失败，停止发布；插件安装器使用其验证恢复点回滚，
激活器恢复 `releaseReady=false`，lane 安装器恢复其 LaunchAgent 之前状态。禁止把本地
synthetic 或 parser 验证写成真实 Telegram 网络验收。

## 发布过程偏差

初版 `install-aiworker-task-flow-skill.sh` 未解析命令行模式，错误地接受了
`--dry-run` 并执行了实际安装。该次执行只替换了目标 workspace 的 task-flow skill 和
受管 Markdown 段，并创建一个可验证恢复点；插件仍为 `0.4.1`、`releaseReady` 未设置、
lane 未加载，未创建任务、n8n execution、媒体或 SQLite 记录。后续版本必须显式要求
`--dry-run` 或 `--apply`，dry-run 只在物理临时目录生成比较材料，且其不变性由回归测试
覆盖。发布在修复通过并重新获得 dry-run 证据前暂停。

首次 lane dry-run 还发现校验器错误地把 `second-original` 的全部路由当作 Telegram
路由计数，因而将同一 agent 的合法 WhatsApp 路由误判为冲突；当时未创建 LaunchAgent、
lane、任务或媒体。校验器已改为只统计 Telegram 路由，并加入该双路由情形的回归测试；
发布继续保持关闭闸门，等待该修复通过验证并更新同一生产仓库。
