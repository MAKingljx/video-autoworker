# 2026-09-09 视频学习排队与导演脑审核反馈修复

## 需求与范围

用户反馈视频在前夜入队后，次日上午仍显示“已排队”，询问进度时只得到“完成后再查询”；导演脑作品候选提交后，回复“批准”却显示暂时无法读取。要求查明原因并完成优化部署。业务状态、诊断和恢复能力继续放在 AI-worker 的平台适配层，不修改 OpenClaw 基础代码。

## 生产诊断事实

- 默认生产节点为第二台 Mac Studio。检查覆盖实际监听进程、运行目录、安装合同、应用发布版本和数据库打开文件身份。
- 稳定路由和应用运行正常，任务入口接受新任务；视频执行 lane 仍处于维护状态，有一个存活的 guardian 持续续期启动锁，lane 未加载且没有视频工作进程。
- 本次原始视频任务已持久化，尚无平台执行记录，状态从提交后一直没有推进。因此不是“只在完成时读取进度”，而是没有真正开始执行。
- 提交接口忽略工作进程启动失败的返回值，查询接口没有执行服务可用性字段，造成模型把维护阻塞解释成正常排队。
- 使用与 Qwen Gateway 相同的服务环境，在独立 Aqua 只读任务中验证导演脑：11 张表结构校验通过；对应作品候选确实存在，仍为草稿且未审核。普通搜索默认只读取审核通过的记录，查草稿须明确指定状态。没有修改任何候选或审核状态，临时检查任务已卸载。
- 聊天工具没有批准或驳回动作。保留会话的工具参数和结果已脱敏，无法据此还原截图当时的精确异常；SSH 环境的凭据访问结果不能替代真实 Gateway 服务环境的验证。

## 修复决策

1. 分开返回任务状态、执行服务可用性和已观测到的处理阶段。维护阻塞必须如实呈现；不能推断队列前面有其他任务，也不能编造完成百分比或启动时间。
2. 提交和查询共用同一套只读状态识别。受控 guardian 不允许被普通提交请求自动删除；锁身份不完整时返回“尚未确认”。
3. 导演脑审核请求给出明确能力说明，不再诱导用户通过没有实现的聊天动作批准候选；不自动转而执行 shell 或搜索来模拟审核。
4. 在适配器日志中保留白名单错误码及动作名称，拒绝记录请求正文、标识、响应正文、凭据或堆栈。
5. 共享组件安装和维护恢复分别验证当前应用、控制层、工作流与插件来源，允许各组件有独立版本。恢复原任务时保留原始任务和幂等标识、历史隔离收据与回滚资料。

## 候选实现与验证

此节所述源码属于本地候选，生产部署事实以本文件后续验收记录为准。

- 导演脑增加只读审核能力说明，显式审核指令的短路处理，以及不含业务内容的错误诊断。完整插件 265 项测试通过，包含凭据缺失不误判为候选内容错误的回归用例。
- 视频插件 137 项、任务流 119 项测试通过；共享安装门禁、当前版本恢复基线与历史 guardian 交接共 86 项测试通过，覆盖原任务不变、拒绝漂移和多处进程中断恢复。
- 任务流和导演脑安装器分别通过安装后重复执行的验证。三个安装器均携带同一队列摘要，安装前、取得锁后和发布成功收据前检查，防止任务内容在维护期间漂移。
- 类型检查通过；Lint 无错误，保留 12 条未受本次改动影响的历史警告；源码扫描无敏感信息发现。完整 CI 和生产验收尚待执行。

新增维护恢复入口为 `scripts/verify-guardian-resume-baseline.mjs` 与现有 guard 的 `resume-guardian` 子命令。恢复基线分开绑定应用版本、历史管理器版本和新共享组件源码；逐文件核对已安装的任务流、视频插件与导演脑插件。原维护收据和隔离树不变，新恢复 attempt 独立保存 baseline、intent、admission、receipt 和提交标记。

## 部署与回滚要求

部署前保存受限备份和当前组件、任务、进程身份；暂停新任务入口后安装经验证的 canonical 源码。安装过程中保持原有 guardian 和队列内容不变。随后通过有收据的正式交接恢复唯一视频工作进程，确认原任务出现真实阶段推进，再恢复入口。

不得重复提交任务、恢复旧隔离素材、删除数据库或索引、自动批准导演脑候选，也不得重放历史一次性部署授权。失败时保留维护状态和诊断证据，通过对应安装器回滚受影响组件。

## 已知限制与下一步

历史维护恢复脚本将当前进程绑定到旧维护时的 PID，并假定各组件同一版本，与已完成的分组件升级不相容。本次增加窄化且可验证的恢复流程，不放宽原历史收据的保护规则。最终验收须区分“修复已部署”“原任务已开始”和“视频已完成”，不能混为一项结果。
