## 3017 Gateway 状态误报修复

### 根因与范围

- 生产机上的三个 OpenClaw Gateway 均已通过本机深度连通性探测并监听各自 loopback 端口，但 3017 的配置档页面把它们统一显示为错误。
- 根因是独立 runtime release 直接经过 `start-standalone.sh` 启动时，没有继承本机 profile target；状态接口因而退回为 SSH 探测，并尝试经失效的主机解析路径访问本机。
- 本次只修正控制台运行环境：生产机检测到本地 OpenClaw 二进制时默认使用本机调用。Gateway、n8n、Qwen 服务、视频 lane、任务、媒体和数据库均不在改动范围内。

### 实现、验证与回滚

- `scripts/start-standalone.sh` 现在在受控生产主机上设置 `MC_OPENCLAW_PROFILE_TARGET=local`，并复用受控的 `OPENCLAW_BIN`；显式指定的 target 保持优先，不影响远程控制台或测试环境。
- 新增 standalone 启动脚本回归测试，覆盖本机 target 与二进制路径约束；同时执行 Bash 语法检查、完整单元测试、类型检查、静态检查和生产构建。
- 发布时只构建新的独立 3017 runtime release 并切换该端口。若验收失败，停止新的 3017 进程并从已验证的上一 release 恢复；不需要回滚数据，也不重启 Gateway、n8n 或视频 worker。
