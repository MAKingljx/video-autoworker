# 2026-09-04 导演提炼安全边界与单一任务链收敛

## 需求

- 统一候选校验、历史 seed 脱敏和飞书写入前的敏感值识别，覆盖 Bearer、JWT、GitHub、Slack 与常见凭据赋值，同时避免把普通叙述中的 `token`、`key` 术语误判为凭据。

## 决策与实际改动

- 新增单一共享敏感值扫描模块；候选与飞书边界检测到敏感值即拒绝，历史 seed 使用同一规则确定性脱敏。
- 直接重写尚未发布的 `058_director_extraction_task_runs`：确定性 succeeded root 的 input 持有唯一 binding，output 仅保存 input digest 注册收据；每个提炼阶段使用独立 phase task run 和复用的 child lease。
- checkpoint 仅保存不可变阶段输入/候选工件；投影和人工复核分别写入按 phase task 键控的 append-only receipt。整体状态由 root、phase 终态、checkpoint 与 receipts 派生，不再持久化 `status/currentPhase/revision` 或可变 checkpoint 投影字段。
- 删除未发布的 `060` 候选与拒绝账本；outbox 只引用 extraction root，并从 root input 派生作品/视频绑定。旧的未绑定成功视频 input 保持字节不变。安装器、standalone 成员与发布 payload 清单继续纳入共享扫描模块。
- backfill 的 `limit` 改为每轮成功登记上限，并以 `20 × limit`、最高 `2000` 条候选做有界 scan-through；本轮确定性坏源只计 rejected 并继续向后扫描，不创建拒绝账本或第二状态机。

## 导演脑 v2→v3 迁移安全闭环

- 需求与决策：只在本地候选实现迁移防护，不连接真实飞书写端。legacy bootstrap 不再承担 schema
  迁移；v2→v3 的唯一写操作是创建 14 个缺失字段，记录更新/删除、既有字段更新/清理、表创建/删除/
  重命名均不在迁移能力内。缺少 `works` 表的 v1 catalog 因此失败关闭，不伪装成可安全迁移。
- 备份与准入：`migrate --prepare --receipt-file` 真读远端完整表、字段和记录，并把快照与原 catalog
  精确字节写入仓库外 `0600` 私有文件。跨进程收据绑定 SHA-256、字节数、权限、UID、GID、
  device/inode、硬链接数、物理路径、目标 schema 摘要和远端摘要，并用同一打开文件描述符完成内容与
  元数据绑定，拒绝读取过程中的路径替换；`migration-backup verify --receipt-file --expected-sha` 可由
  全新进程独立复验，不再依赖 `WeakSet` 或其他内存对象身份。
- 应用与并发：`migrate --apply --receipt-file --expected-sha` 在同一 catalog 目标锁内再次校验收据、
  catalog 原始字节、远端稳定表身份和独立 revision。每个 `createField` 只有在 API 明确返回字段身份且
  私有进度收据持久化后才归迁移所有；真实中断可按收据续作，响应丢失或并发同名字段不被静默认领。
  锁绑定目标、收据 SHA、owner UID 和不含命令行的进程 incarnation；incarnation 的 `ps` 采样固定为
  `TZ=UTC`、`LC_ALL=C` 并同时校验进程 UID，避免不同时区或 locale 把活 owner 误判为遗留进程。
  SIGKILL 遗留锁仅在 owner 已死亡且完整匹配时归档恢复；恢复路径由旧 owner token 唯一确定且不可覆盖，
  搬移后还会复核锁目录及 owner 文件的 device/inode、摘要和 UID。并发恢复失败方只返回 contended，
  不会把另一个恢复者刚建立的后继锁搬走，也不会把启动参数写入锁收据。
  字段全部回读确认且记录零变化后才原子推进 catalog 版本，并落私有应用收据保存新增字段 ID。
- 回滚边界：`migrate --rollback-dry-run --receipt-file --expected-sha` 全程只读，在同一迁移锁内双采样，
  返回两次采样时间和远端摘要，并核对新增字段 ID、类型、选项、空值、catalog 应用身份与业务记录。
  未证明归属、字段已有值、字段漂移、revision 异常、任意业务写入或两次采样漂移都会明确拒绝；没有

## 导演脑系统问题硬路由合同修正

- 截图中的“技法底层逻辑”问题先进入普通 Agent 长会话，约 `205,812 B / 55,111 tokens` 的历史在模型前自动压缩失败，因而没有机会调用导演脑 `explain`；这不是飞书额度或导演脑内容缺失。
- 早期候选沿用了视频入口熟悉的 `before_dispatch`，只能从 session key 推断 Agent。按本机 OpenClaw `2026.7.1-2` 真实源码复核后，系统问题入口改用官方 `before_agent_reply`：事件读取 `cleanedBody`，上下文用 `ctx.agentId` 精确限定目标 Agent，返回 `{ handled: true, reply: { text }, reason }`，在模型运行和自动压缩前短路。
- 非 bundled 插件必须设置 `plugins.entries.aiworker-director-brain.hooks.allowConversationAccess=true`。安装器、runtime convergence manifest、fresh-start readiness 和 runtime inspection 统一要求 `before_agent_reply`、`before_message_write`、`tool_result_persist` 三个 hook，不再保留两套运行合同。
- 真实 OpenClaw 写入顺序已确认是 `tool_result_persist` → `before_message_write` → JSONL。候选实现把 `before_message_write` 补成可独立处理原始 `toolResult` 的最后防线；第一层已投影的结果再次经过第二层保持结构相同，工具名与调用 ID 不变。缺失工具名时只保留无敏感正文的失败/成功状态，不虚构配对标识；无法核实目标 Agent 时不跨 Agent 改写。
- 两项同步持久化 hook 使用显式低优先级，按 OpenClaw “高优先级先执行”的真实合同在其他正常消息处理后收口。`before_agent_reply` 同时声明 `eligibleTriggers=['user']`，宿主门禁和 handler 内部检查双重排除 heartbeat。
