# 2026-08-11

## 视频任务状态查询误判事故

一次已授权 Telegram 私聊自然语言请求由 `0.3.0` 原生插件正常派发。生产只读
核验确认，父任务与 `prepare`、`audio`、`vision`、`finalize` 四个阶段全部首次
成功，音频转写和纯色画面识别均产生了有效结果；n8n 只执行正式
video-analysis 链，没有 generic 工作流增量，也没有重复视频任务增量。

随后用户在新消息中自然询问进度。生产插件当时只确定性接管提交、说明和拒绝，
没有在 `before_dispatch` 接管状态意图，该消息因此进入 Qwen。Qwen 没有调用正式
的单次状态客户端，而是连续进行 46 次 `exec` 和 3 次进程操作，多次触发循环
保护，并误读前一天遗留的本地 QA 工件。该旧工件与本次视频、任务和结果无关，
其空载荷被错误解释成“本次分析没有有效内容”。查询期间 Mission Control 任务和
generic 工作流均零增量，因此事故是错误查询与错误回复，不是视频主链失败或
重复提交。

本记录只保留脱敏计数和因果关系，不记录完整任务编号、本机绝对路径、会话标识、
聊天正文、PID、原始日志或数据库内容。

## 修复契约

本地 `0.4.0` 候选将状态查询与视频派发收敛到同一会话入口。后续“查进度”、
“查一下刚才的视频”或带完整任务编号的消息，由原生插件在 `before_dispatch`
阶段确定性接管，不再交给 Qwen：

1. 状态请求先复用授权 Telegram 私聊身份门。
2. 任务编号只接受当前消息中的完整编号，或插件受信且唯一的最近回执绑定；没有
   可信编号、编号不完整或存在歧义时，只要求用户提供完整任务编号。
3. 解析出唯一编号后，专用状态 runner 只调用一次正式只读状态客户端，并立即
   返回一条 `任务已受理，正在等待处理。`、`任务正在处理中。`、
   `任务已完成。`、`任务处理失败。` 或 `暂时无法查询任务状态。` 的人类短回复；
   普通状态回复不重复冗长任务编号，成功或失败只可追加正式接口返回的安全限长
   摘要或原因。
4. 状态轮次禁止 Qwen、工具搜索、记忆搜索、文件搜索、直接 SQLite/n8n 扫描、
   进程管理、轮询、重试、重提和 generic fallback。只有正式返回
   `succeeded` 才能报告完成。

静态契约测试同步覆盖 skill、workspace 规则、受管 MEMORY 模板和架构文档，防止
后续把状态请求重新退化为模型自由搜索。插件实现、生产部署和真实 Telegram
验收须分别提供代码测试、运行时与生产证据；本节本身不冒充部署完成。

## 本地候选与发布边界

`0.4.0` 继续保持单一 hook-only 插件：仍只注册一个 `before_dispatch`，不重新引入
可选模型工具、prompt/tool hook 或运行状态机。状态解析、最近任务指针、只读状态
调用和短回复分别放在小型独立模块中；提交和状态调用复用同一个受限 JSON 子进程
边界。最近任务指针只在插件内存中保存 24 小时、按 Telegram 私聊会话和发送者
哈希隔离，不写聊天正文、视频路径或数据库；Gateway 刷新后若指针不存在，用户需
提供回执中的完整任务编号。

本地 Node 22 最终验证结果为：插件 22 个文件、321 项测试全部通过；应用仓库
101 个文件、1030 项测试全部通过；TypeScript、目标 ESLint、相关 Node/Bash 语法
和 `git diff --check` 全部通过。测试覆盖一次查询零提交、最近回执与显式完整编号、
控制字符和多编号拒绝、结果/完成自然问法、无关订单消息放行、installed synthetic
状态验收，以及 `0.3.0` 到 `0.4.0` 的 apply、自动恢复、显式回滚和失败补偿。

受控升级入口固定要求显式 Git SHA、canonical main 与 GitHub main 一致、工作树
干净、生产身份和 OpenClaw 版本匹配。它只允许刷新 `qwen-current`，并固定核对
Mission Control、n8n、共享模型和其他 OpenClaw profile 的监听进程不变；候选任一
payload、索引、runtime、live Gateway、effective tools、配置或监听门失败时，恢复
精确 `0.3.0` 插件与配置。历史可恢复备份只在全部 live 门通过后收敛到最多两份。

本地候选不会生成独立视频分析报告文件。正式结果仍保存在 Mission Control 任务
记录中，n8n 保存工作流执行证据；`finalize` 后受控媒体工作目录按任务范围清理。
状态查询只读取正式任务接口，不扫描文件、SQLite 或 n8n。发布完成前，本节不得被
解释为生产已经升级或真实 Telegram 状态入口已经验收。
