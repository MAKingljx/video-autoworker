- 该结论不能升级为完整法证定论：部署前门禁只记录了文件数量，没有保存旧文件的脱敏路径映射、大小和哈希，运行时也没有逐文件删除审计。不得补造缺失证据、猜测原始来源或在没有新授权与可靠恢复源的情况下尝试恢复。插件与视频链功能验收可记为通过，但“历史 inbox 保持不变”这一治理验收项明确未通过，整轮不能表述为无异常完成。

### 修复候选与最小部署边界

- 修复候选从 `prepare` 请求热路径移除全局 TTL 扫描，并删除应用运行库中对应的自动清理入口；prepare 还会在创建子任务前要求请求视频键与父任务持久化的视频键完全一致。单任务自己的 staged 副本和终态工作目录才可按该任务范围消费，不扩大为保留每个临时副本。
- 历史媒体治理改为独立审计入口 `scripts/aiworker-media-retention.mjs`，实现库为 `scripts/lib/aiworker-media-retention.mjs`。当前候选仅支持审计模式，调用时必须显式使用 `--dry-run`；它先对生产主库/WAL 做前后强指纹并复制到权限受控的临时快照，只在快照上执行 `query_only` 与完整性检查，结束后清理该精确临时目录，不让 SQLite 接触或生成生产 sidecar。唯一保留的写入是调用者指定、位于源码树和媒体根之外的 0700 目录中的 0600 审计计划；畸形任务输入会让整次审计失败关闭。`--apply` 与 `--delete` 会被拒绝，没有媒体恢复或删除能力，也不在正常视频请求中自动运行。任何后续保留、恢复或删除都必须另立任务、补齐证据并取得明确授权。
- 本候选只涉及 Video AutoWorker 应用代码、测试和脱敏文档；不修改 n8n release 或工作流，不修改 OpenClaw 插件、模型路由、数据库 schema 和历史运行数据。后续生产部署只允许重新构建并刷新 `3017`，必须保持 n8n 与 OpenClaw Gateway 进程不变，并复验两库、服务健康和只读审计输出。当前记录只描述候选和部署边界，不把尚未执行的生产部署写成既成事实。
