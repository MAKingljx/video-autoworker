### 根因结论

本次截图事故的可证根因不是 n8n 执行失败，而是任务根本没有提交到 n8n。OpenClaw 在原会话中走了临时命令、直接媒体处理和轮询旁路，形成多轮工具调用与重复进度播报，最终触发上下文容量问题。端口、Gateway 和模型服务在线不能推翻该结论，因为任务库与执行库在对应时段均没有正式链路活动。

正式流程统一为：

`User -> OpenClaw -> aiworker-task-flow -> Mission Control / SQLite -> n8n -> prepare -> Whisper audio + local Qwen vision -> finalize -> SQLite -> status query`

OpenClaw 每次只提交一次并立即返回异步回执；同一轮不得轮询，不得直接运行旧视频学习流程或临时媒体脚本。Whisper、Qwen 和最终工作节点均保持 `memoryMode=none`。
