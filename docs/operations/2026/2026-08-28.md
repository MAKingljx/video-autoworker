## 需求与现象

- 修复视频工作流已经返回受理、但没有建立任何媒体阶段时，父任务永久停留在非终态并阻塞全局串行队列的问题。
- 已确认 n8n execution `66` 的首个媒体回调因认证返回 HTTP `401`；对应平台 task row `274` 留在 `accepted`，且没有 `prepare`、`audio`、`vision` 或 `finalize` 子任务。
- 目标 24 集批次当前完成度为 `0/24`。worker 每次恢复都会先遇到同一条孤儿父任务，因此后续项目持续处于队头阻塞状态；这不是 24 个视频分别失败，也不是模型推理速度问题。

## 根因

- 触发端在共享 Webhook secret 缺失时仍可创建父任务并调用 n8n，未在持久化任务前 fail-fast。
- 原视频工作流先返回 HTTP `202`，再发起媒体回调。平台据此记录 `accepted`，但回调认证失败后没有路径把父任务收敛为终态。
- 原任务状态机没有面向“已受理但从未建立媒体阶段”的租约回收；worker 只能重复读取同一个非终态记录。
- 单一全局 video lane 为刻意保留的资源保护边界，但原 drain 策略会在当前批次仍需恢复时退出，因此队头孤儿会同时阻塞同批次剩余项目和后续批次。
- 仅增加超时更新仍不足以安全修复：若回收检查与迟到媒体回调并发，回调可能在检查后创建子任务，甚至重新推进已经失败的父任务。

## 设计决策

### 触发与 Claim

- `N8N_WEBHOOK_SECRET` 缺失时，触发 API 在读取生产数据库和创建父任务前返回 HTTP `503`；底层 Webhook 客户端再次校验，避免其他调用方绕过入口门禁。
- 视频工作流调整为先调用受认证的父任务 Claim 接口，Claim 成功或命中同一任务的幂等 `running` 状态后，才构造并返回 HTTP `202`。
- Claim 使用任务 ID、幂等键、binding、tenant 和 workspace 的同一作用域校验，只允许 `queued/accepted -> running`；失败、成功或取消任务不会被重新激活。

### 900 秒租约收敛

- 对 `video-analysis` 父任务采用默认 `900` 秒回调租约。
- reconciliation 使用 scope-aware SQL compare-and-swap，只处理租约已过、状态为 `accepted/running`、且四个确定性媒体子任务均不存在的父任务。
- 收敛结果写入稳定错误码和明确完成时间。只要任意媒体子任务已经落库，长视频无论运行多久都不会按 pre-media 孤儿回收。
- reconciliation 由显式内部 POST API 执行；只读任务查询接口不暗中写库。

### 迟到回调与 worker

- 媒体子任务创建改为 `IMMEDIATE` SQLite 事务：事务内重新读取父任务、拒绝终态父任务，并创建或读取确定性子任务。该事务与 reconciliation 的写锁互斥，关闭“检查后迟到创建”的竞态。
- worker 在等待已存在的非终态平台任务期间按约每分钟调用一次 reconciliation；首次检查通常在等待约 `60` 秒后发生，新提交后才成为孤儿的任务不必等待原有长超时窗口。
- reconciliation 将任务转为 `failed` 后，现有平台终态权威逻辑负责更新持久批次并继续同批次下一项；失败项目不会重新提交。

### API 契约

- 新增内部 Claim 与 reconciliation API 契约，补齐 OpenAPI 定义。
- API 路由与 OpenAPI 的 parity 检查已通过；没有通过忽略项掩盖新增接口。

## 回滚计划

- lane 恢复前是首选自动回滚窗口。若任一验收失败，保持 lane 停止，按相反顺序恢复上一 3017 release、上一视频工作流和 task-flow 验证备份。
- n8n 回滚必须离线执行，只恢复视频工作流与上一 runtime 指针；不得重导或覆盖无关工作流、execution 或凭据。
- 若需要撤销 task row `274` 的 reconciliation，只从一致性备份中恢复该行被修改的状态字段，并以当前错误码和任务身份作为 CAS 前提；不得直接覆盖整个生产数据库。
- lane 恢复后，如果后续项目已经提交或产生新的 n8n execution，不得直接还原批次文件或整库快照，以免重复提交。应立即停止唯一 lane、保留现场并制定前向恢复方案。
- 所有回滚都保留新 release、日志和受控备份作为证据，不删除媒体、索引、任务状态或模型资产。

## 已知风险

- n8n 视频工作流离线更新需要短暂停止 n8n；停机窗口内不能接受新工作流触发。
- 恢复唯一 lane 会立即重新扫描持久队列，可能开始处理 row `274` 后面的下一项；因此它必须是所有代码、工作流、数据库和人工队列确认完成后的最后一步。
- `900` 秒只覆盖“尚未建立任何媒体阶段”的启动租约，不是长视频执行总超时。后续若工作流在高负载下可能合法地等待超过 900 秒才创建首个媒体子任务，需要基于真实启动延迟指标调整，而不是直接扩大总任务超时。
- task-flow 安装器会同时维护受控 workspace 规则与记忆段；发布前后必须校验事务备份和安装 payload，不能直接覆盖已安装 skill。
- 本地定向测试不能替代生产真实入口验证；但生产验收不得为了证明修复而重提 row `274` 或额外创建重复视频任务。
