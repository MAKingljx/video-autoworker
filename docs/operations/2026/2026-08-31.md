## 安全修复

- 正式素材证据转换器仍校验分段转写字段类型，但不再投影分段原文或“声音信息”，也绝不使用包含逐段转写的 `combinedText` 作为证据摘要；只有受治理的 `output.summary` 可以进入摘要，缺失时失败关闭。
- 运行时读取要求记录包含准确项目 ID；作品业务还必须包含并匹配作品 ID，缺失或错配时失败关闭。
- `reviewed=true` 不再只看状态值，还要求领域必填字段、合法语义版本、来源、更新时间以及表结构要求的审核人、审核时间和审核原因全部有效。
- 默认搜索、六层工作流和上下文组装只接纳完整审核契约；按稳定业务 ID 显式读取候选时保留 `reviewed=false`。未审核导演案例不会输出“成片位置”。
- 请求和远端返回均拒绝所有 HTTP/HTTPS URL，防止飞书资源链接或普通外链绕过资源边界。
- 全片摘要只绑定覆盖完整媒体时长的全局证据；局部时间段只使用同段结构化视觉观察，不能把全片结论重复绑定到局部时间码。已有 `materialId` 原样复用；没有时按文件内容生成稳定 ID，随机收件箱 `videoKey` 不再冒充长期素材身份。
- 所有审核路径在实际更新前重新精确读取并比较完整记录快照、版本、状态、record identity、项目和作品归属，写后回读；搜索与六层工作流统一拒绝重复稳定 ID，请求和远端文本同时拒绝明显飞书内部资源 ID 形态。
- 本地候选已形成可恢复的媒体交接状态机：源文件绑定 `dev/ino/size/mtime/ctime`，暂存成品绑定内容 SHA-256、任务、幂等键、批次、随机所有权令牌和受控 `materialId`；持久化阶段覆盖 `prepared -> anchor_observed -> copy_observed -> source_finalized -> staged -> triggering` 以及 `discarding_prepared -> discarding`。生产者按任务维护持久 outbox，消费结果不确定时保留并复用同一任务、素材 ID 与 nonce；消费者先把交接身份写入任务级 WAL，再写入正式单任务状态并返回持久 ACK，生产者只在该 ACK 后删除 outbox。
- macOS 跨卷路径在 hard-link 完成后、复制开始前立即持久化 `anchoredIdentity`。恢复时必须同时匹配生产者 outbox、消费者状态、锚点 inode、所有权令牌和 checkpoint 身份；checkpoint 后的 `chmod`、`chown`、来源漂移或冲突均失败关闭。崩溃恢复只处理身份精确匹配对象，归属不明时进入 `attention` 并保留现场，不猜测删除、重提或串用其他媒体。
- 已存在但仍停留在 `queued` 的同一任务，只能用原任务 ID、幂等键和同一 `videoKey` 有界续派；其他非终态或终态重复请求不会重新派发。Webhook 响应不确定时以平台 Claim 后的正式状态为准，不能把已运行或已成功任务误记为失败。
- `finalize` 必须先确认 `prepare/audio/vision` 三项正式输出；最终输出携带受控 `materialId`、媒体时长和分析版本。finalize 子任务与父任务终态由同一 SQLite 事务提交，已成功 finalize 可修复旧运行时遗留的父任务未完成状态；运行中的 finalize 另有独立 `24` 小时 hard lease，超时后父子任务原子失败并阻断迟到回调。
- migration `051` 新增持久媒体清理债务：成功 finalize 或 hard lease 超时的父子终态与清理责任在同一事务记录。独立 janitor 每 `5` 分钟只读取到期债务、不扫描媒体目录；重试前校验作用域、工作流绑定、工作区摘要和父子终态，失败按有上限的退避继续保留债务，且不回滚已提交的父子终态。这套 journal 与清理债务只维护交接恢复和终态后的资源回收，不创建第二套业务任务状态机；平台 SQLite/API 仍是任务、父子阶段和最终结果的唯一权威。
- 上述媒体身份、崩溃恢复和续派增量仍是本地候选，尚未部署到当前 `542eebd-runtime`；不得把本地测试通过写成生产已生效。
- 安装器在既有 `plugins.allow` 存在时只保留原名单并追加导演脑插件，不会重新放通被排除插件；回滚点使用覆盖目录、文件、权限和摘要的全树清单，额外、缺失或漂移成员均拒绝恢复。
- standalone 清理器改为物理目录边界校验和精确准入：任何写入前先拒绝异常祖先符号链接，pnpm 源 store、依赖目标或链接边界缺失时失败关闭；构建机路径从 `server.js` 与 `required-server-files.json` 清除，source map、trace manifest 和源码扩展均不进入最终 release。
- 最终 release 生成覆盖目录、普通文件摘要与符号链接目标的 SHA-256 清单，启动前重新验证；运行数据、数据库、token 文件和 PID 必须是 release 外的绝对路径，物理解析后落回 release 的路径会被拒绝。基础 schema 同样拒绝符号链接、空白内容、缺少核心表或关键列的伪 schema，失败事务不会错误记录 `001_init`。
- 部署器只停止经 PID、监听端口、进程工作目录和旧 release 身份共同验证的进程；构建前保留独立恢复 release 和旧进程实际使用的外部数据绑定。SQLite 迁移遇到 WAL、SHM 或 journal 时必须安全合并或失败关闭，不能整目录覆盖。新进程还需验证实际数据库、token 和 PID 绑定没有被环境覆盖；页面、API、数据库和 release 清单全部验收前保留恢复副本，失败时只恢复旧 release 及其原外部绑定，不回滚任务库或其他受保护服务。

## 回滚与已知边界

- 本机插件安装可使用安装器生成的已验证回滚点恢复；回滚同样不自动重启 Gateway，也不触碰飞书数据或任务链。
- 飞书审核记录当前没有密码学签名。具备直接编辑权限的人如果完整伪造全部审核字段，运行时仅凭记录内容无法识别；生产化必须补齐最小权限、独立审核入口和审计告警。
- 飞书记录更新接口没有跨 UI 的原子条件更新。服务会在写前再次比较完整快照并写后回读，但直接编辑者若恰好在最后读写窗口内并发修改，仍需依赖最小权限和异常变更告警控制风险。
- 表结构、验收样片和六层就绪只证明契约闭环，不证明真实项目上的人物、故事、七维判断、叙事脚本、案例与技法学习已经稳定生产化。
- 除剪辑执行外，仍未生产化的范围包括：远端正式完成事件到导演证据的自动投影、失败重放与告警、限流和长期负载、真实素材上的人物消歧与跨日期更新、故事与因果发现、七维判断、叙事脚本、案例与技法学习、审核真实性与最小权限、多用户授权、导演脑管理界面及灾难恢复演练。
- release 清单用于发现构建后漂移和意外运行时写入，不是代码签名；生产供应链真实性仍依赖受控 Git 提交、严格快进、目标机本地构建及发布审计。
