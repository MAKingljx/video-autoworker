# 2026-08-20 视频重复门禁、正式结果工作台与组件库评估

## 需求

- 视频提交遇到同名或同真实路径历史记录时，先提示用户确认；只有后续明确回复“确认重新分析”才允许创建新任务。
- 在 `/materials` 增加正式视频分析结果明细，与历史素材检索明确分离，并支持列表、搜索、筛选、分页和完整结果查看。
- 继续收敛全站配色，主体只使用中性色与一个主色，绿、黄、红只承担成功、警告和错误语义。
- 核查 Phoenix 组件库能否直接替换当前页面组件，并把本项目缺少的通用组件登记到组件库。

## 本地候选实现

### 重复视频确认门禁

- `aiworker-task-flow` 在创建任务状态、复制媒体或触发 n8n 前，按 `realpath` 后的真实路径和文件 basename 检查历史任务；目录中任一视频命中时阻断整批提交。
- 首次命中只返回固定确认提示，不创建状态文件、不复制媒体、不启动 worker、不触发 n8n。只有用户后续精确回复“确认重新分析”并由插件传入 `confirm_duplicate` 后才放行；模型不得在同一轮自行确认。
- 同一任务 ID 的幂等重试继续返回原任务状态，不被误判为新建重复任务。插件候选版本由 `0.5.8` 升为 `0.5.9`，升级入口同步更新版本契约。

### 正式视频分析结果

- `/api/n8n/runs` 新增 `view=video-results`：列表查询使用 `limit/offset/query/status`，详情使用 `taskId`；两者都严格按当前 workspace/tenant 隔离。
- 接口只投影标题、状态、任务/批次信息、摘要、章节、时间线、语音转写、画面证据和正式报告，不返回原始路径、input、prompt、routing、delivery、workers 或模型路由。
- 列表由 SQLite 直接提取短摘要、章节数和时间线数，不再把每条完整报告加载到 Node；只有打开单条详情时才读取并清洗该任务的正式输出。
- `/materials` 顶部新增“素材检索 / 分析结果”切换。分析结果采用响应式主从布局，包含搜索、状态筛选、分页、刷新、摘要、章节、时间线、音画证据和完整报告；只有唯一匹配本地片源时才展示播放器和时间线定位。

### 配色收敛

- 登录、加载、导航、仪表盘、聊天、设置、任务、素材和主要管理面板统一到中性色表面与单一主色；模型类型、普通标签和装饰元素不再各自分配高饱和颜色。
- 办公室可视化保留结构性主色网格和语义状态点，移除时段渐变光效、闪烁星点、热力光斑、发光阴影和多色角色变体。遗留 `glow-*` 类仅为兼容保留，实际不再产生发光。
