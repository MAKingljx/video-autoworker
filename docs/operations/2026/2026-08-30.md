- Video AutoWorker 项目内的独立“导演脑”飞书自建应用已经发布 `1.0.0`，发布页面显示当前修改均已发布。
- 独立导演脑多维表格已经创建，包含系统蓝图、导演意图、素材证据、人物档案、故事节点、故事关系、素材判断、叙事方案、导演案例和技能技法库 10 张表。
- 10 表字段契约已通过真实飞书 API 精确核验；8 条系统蓝图已按稳定 ID 写入并逐条精确回读。
- 临时记录的创建、更新和删除已通过真实 API 验收，最终残留为 `0`；远端种子内容与敏感模式扫描均通过。
- 当前完成范围是独立飞书云端基础设施，不是运行时业务接入。真实素材自动入库、自动故事脚本生成和 DaVinci 实机剪辑均未完成。
- 本轮未修改、重启或切换生产 `3017`、n8n、Gateway、video worker、正式任务或数据库。

## 需求与决策

用户希望把飞书作为 Video AutoWorker 的“导演脑”云脑，长期积累素材理解、人物认知、故事发现、素材价值判断、叙事方案、导演案例和技能技法。

导演脑使用项目测试飞书账号构建独立应用和独立数据空间，与现有飞书工作大脑隔离；但它仍属于 `PROJ-VIDEO-AUTOWORKER`，不是新的逻辑项目。已有 task、batch、material、scene 和 shot ID 原样复用，不能因为迁移到飞书而再次生成来源身份。

现有飞书工作大脑继续保存项目规则、决策、计划和任务；导演脑保存纪录片领域知识与导演判断。两者物理隔离，但导演脑未来只能作为现有唯一视频任务链的长期知识与决策子系统，不能维护任务状态机、队列、重试、取消、重提或媒体处理副作用。

飞书只保存结构化知识、来源 ID、证据时间码、版本和置信度。原始视频、逐帧图片、完整原始转写、向量、日志、数据库、任务状态和凭据继续留在受控本地系统。自动内容必须先进入候选或待审核状态；高层判断必须回链到素材证据和导演意图版本。

## 安全检查

- App Secret 只存放在独立 Keychain 项中，没有写入代码、schema、文档或 Git。
- 本地资源目录保存在仓库外，并使用受控文件权限。
- schema 主动拒绝名称包含 secret、token、password、密码、密钥或私钥的字段。
- 记录写入主动扫描私钥、常见 API Key 和 secret 赋值模式。
- `.PhoenixBrain`、本地资源目录、凭据、临时 API 记录和远端资源内部 ID 均不进入提交。
- standalone 构建会在完成后枚举实际成员；发现 `.PhoenixBrain`、`.git`、任意大小写及扩展形式的 `.env*`、常见包管理凭据文件、私钥文件或本地 catalog 即失败，不依赖 `.gitignore` 作为发布证明。
- 临时写检查带随机稳定 ID，并执行多轮清理及最终残留确认，没有留下测试数据。
- 一次性 Keychain 更新探针在确认无代码或配置引用后已精确删除并验证不存在；正式导演脑专用凭据项未改动。

## 发布与回滚

本次只发布飞书测试环境的独立导演脑基础设施，以及 canonical 仓库中的无密钥 schema、维护 CLI、测试和脱敏文档。没有生产运行时切换，也没有任务数据迁移。

- 本地代码可通过后续 Git revert 撤销，不影响已经存在的 Video AutoWorker 生产运行时。
- 飞书侧如需停用，优先停止后续写入并撤销或限制应用权限，保留当前表与种子作为审计证据。
- 删除应用、表或记录属于外部破坏性操作，必须先盘点资源和引用关系、确认备份与精确范围后另行执行；本轮不删除导演脑基础设施。
- 因本轮未改动 `3017`、n8n、Gateway、video worker、任务或数据库，不存在针对这些生产组件的回滚动作，也不得借导演脑回滚重启或恢复它们。

## 已知问题与当前限制

- 除系统蓝图外，本轮没有向其他领域表导入真实素材、人物、故事、判断、叙事、案例或技法数据。
- 还没有定义正式素材分析结果到“素材证据”表的完整字段映射、幂等写入、重放和冲突处理协议。
- 人物跨日期更新、故事关系发现、导演价值判断和导演案例学习闭环仍是数据结构与开发目标，不是已经运行的自动能力。
- “故事脚本”字段只作为叙事方案契约预留，不表示当前系统会自动生成可交付脚本。
- “剪辑方案 ID”只作为未来 edit-plan 引用，不表示已经连接或控制 DaVinci。
- 尚未完成飞书 API 限流、批量数据、失败恢复和长期运行负载验证。
- 飞书不得成为任务状态权威；后续接入如果反向驱动任务提交、重试或状态变更，将违反当前单链边界。
