# AGENTS.md

## 飞书工作脑管理根

- 本仓库位于本机 `AI-worker/` 工作区内时，整个工作区使用同一 `PROJ-VIDEO-AUTOWORKER`，飞书档案与主 `.PhoenixBrain` 以 AI-worker 根为准。即使从本产品子目录开始，也显式将该管理根传给 `resolve --project-root`；不要在产品内重新生成主标记，不把工作区运行数据整体纳入 Git。
- 独立克隆和远端节点使用其实际核验的项目根与同一仓库身份，不照抄本机绝对路径，不将其他项目并入本项目。
- 执行 `VAW-WORKSPACE-GOVERNANCE-001` 和 `RULE-BACKUP-RETENTION-001`：每个备份集最多保留当前副本外最近两个已校验且可恢复的历史版本，计数覆盖目录和压缩包。临时工作树任务结束后核对引用、改动和数据并退役；未解除的清理条件须列为待处理，不算全部清理完成。Git 历史、源数据和唯一恢复点不得为满足数量而删除。

## 项目记录

- 每个非简单功能、配置、模型路由、工作流、部署、故障处理、需求或架构决策完成时，更新 `docs/operations/YYYY/YYYY-MM-DD.md`，不得只把结论留在聊天记录中。
- 记录至少包含需求、决策、实际变更、环境范围、验证证据、部署与回滚、已知问题和下一步；必须明确区分本地候选、隔离验证和生产事实。
- 代码、n8n 工作流、部署脚本或生产配置发生变化时，对应记录必须进入同一 Git 提交。记录任务本身完成验证后，推送到 GitHub `main`；用户明确要求只分析、禁止写入或禁止外部操作时除外。
- 长期架构和操作方式变化时，同时更新相关 `docs/` 文档；动态运行状态只能作为带时间戳的验收证据，不得写成永久事实。

## 安全边界

- 只提交脱敏结论。密码、Token、App Secret、私钥、聊天 ID、会话正文、原始日志、数据库、素材索引、模型权重、备份内容、缓存、PID 和临时文件不得进入 Git。
- 环境变量只提交无密钥模板；任何真实凭据使用 Keychain、环境变量或外部密钥管理。
- 记录远端验证时可以写主机用途、服务角色和验证结果，但不要提交可用于接管环境的认证材料。

## AI 下载文件管理

- AI-worker 默认生产节点上由 AI 下载或获取的普通外部文件，统一进入 `/Users/Shared/aiworker-storage/ai-downloads/<project-slug>/YYYY/MM/DD/<task-slug>/`，不得散落到桌面、系统下载目录、源码仓库、OpenClaw workspace 或运行时临时目录。
- 未完成文件放入 `_incoming/`，完成大小、格式和 SHA-256 校验后移入 `files/`；权限受控的 `manifest.json` 记录脱敏来源域名、时间、文件名、字节数、SHA-256、用途和状态。
- 模型权重、数据库、备份、密钥、缓存和视频链受控收件箱继续使用各自专用目录。下载内容与敏感清单默认不进入 Git；只提交规范、无密钥模板、管理脚本和脱敏记录。
- 本规则只约束后续下载，不自动迁移、覆盖或删除历史文件；历史整理须先盘点、备份并确认。
- 统一下载目录不是缓存，不设默认自动清理周期；保留、归档和删除必须由任务级策略或用户确认决定。

## 页面视觉

- 页面以中性色为主体，只保留一个主色表达当前选择、主要操作和关键链接。
- 绿色、黄色和红色只用于成功、警告和错误等真实状态；普通标签、模型类型、本地/云端分类和装饰信息不分别使用高饱和颜色。
- 避免彩虹式标签、大面积渐变和无语义发光效果。

## 工程与组件规范

- 修复前先读取当前机器状态摘要、受影响合同、最近一次同类故障和本次 diff，明确唯一权威、状态迁移与失败边界；相同根因只修改一个共享模块，不在页面、平台适配器、脚本和 API 各自追加补丁。
- 为后续 AI 提供有界机器收据，至少包含当前状态、稳定错误码、下一动作、提交、运行 release、路由 generation、数据库身份和证据摘要。项目记录只保留结论、哈希与准确证据路径；原始长日志和模型正文留在受控运行目录，不要求后续任务反复读取。减少上下文不得省略身份、权限、数据完整性、CAS 和真实部署验收。
- 视频能力只维护一条当前任务链。Telegram `before_dispatch`、`aiworker_analyze_video`、控制台 API 和页面只能作为薄入口或只读投影，必须复用同一任务 runner、状态权威规则和数据契约，不得复制成并行链路。
- 功能升级直接迁移当前实现并删除被替代的活动代码，不新增 `legacy`、`v2`、兼容开关或双写分支长期并行维护。生产 release、数据库备份和已验证旧 bundle 只作回滚点，不算可继续开发的第二版本。
- 状态枚举、终态判断、状态权威优先级、输入校验和公共投影等领域规则集中在单一共享模块；第二个消费者出现时必须先抽取复用，不得复制判断逻辑。
- 页面优先复用 `src/components/ui/` 和既有 feature component。新增通用 UI 能力先核对 Phoenix 组件库与项目内现有实现；页面组件负责组合，数据读取、状态仲裁和格式化放入可单测模块。
- 每次改动保持类型严格、接口最小、命名稳定，并为受影响的共享模块、租户隔离、失败降级和关键页面行为补必要回归。遵循飞书全局规则 `SAFE-EFFICIENT-EXECUTION-001`：已验证且未改动、未受本次依赖/配置/环境变化影响的部分必须复用原证据，不因新提交或重新打包重复全量测试；仅执行变更影响范围内必要的测试、类型/lint及构建检查，保留新制品完整性和真实部署健康验收，记录复用与新增验证的区别。
- 不机械附和用户或遵循明显低效流程。遵循 `SAFE-EFFICIENT-EXECUTION-001` v1.1.0：在既有目标和授权范围内自主分析新问题、修复根因并继续，优先长期可维护的共享契约、兼容性和可回滚的小步变更；不因常规缺陷或实现调整反复索取授权。只有超出授权范围、尚未授权的不可逆或重大风险、强制审批、或确需用户决策时才暂停相关动作。重试须有新证据与收敛条件，不重复无效修复或验证。
