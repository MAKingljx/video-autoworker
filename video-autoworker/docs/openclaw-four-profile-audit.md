# H1 四个 OpenClaw 入口审计与升级方案

核验日期：2026-10-14，北京时间10:46起。本文区分生产观察、隔离候选与待实施方案；网关在线不等于模型、工具或消息送达已验收。

## 当前架构

四个入口分别拥有配置、状态、工作区、会话和回环端口，配置权限0600、状态目录0700；共用OpenClaw程序。生产程序仍为2026.9.2，Node为22.22.3。

| 入口 | 配置用途 | 已验证状态 | 当前限制 |

| gpt-main | GPT-6，生产对话与已授权的达芬奇界面操作 | HTTP及认证RPC健康；采样时无活跃执行 | 本次未发送模型推理；若干定时任务持续超时 |
| qwen-current | 千问3.6、飞书、视频与导演脑薄工具 | HTTP及认证RPC健康；飞书connected=true | Telegram反复断开；插件与工具权限需要整理 |
| qwen-weixin-new | 千问3.6、微信入口 | HTTP及认证RPC健康；采样时无活跃执行 | 部分维护子能力失败警告；公开私信策略需要复核 |
| image-studio | 千问3.6对话、Qwen-Image-Edit-2511整图生成 | HTTP健康、服务运行；配置仅授权图片工具 | SSH会话不能解析其既有Keychain SecretRef；本次未验收实际生图；飞书仍未配置 |

这属于进程、配置和业务角色隔离，不属于操作系统沙箱。四者使用同一macOS用户；拥有系统执行能力的入口仍共享用户权限。三个千问对话入口复用同一模型后端，不能由profile数量推断有三份独立模型或三份算力。

图片入口配置为minimal，只增补aiworker_generate_image，明确拒绝执行、浏览器、节点、消息发送、跨会话、定时任务与网关管理工具；没有视频链授权。本次不扩大它的权限。

以上入口表为升级前审计采样。2026-10-14生产四入口已切换2026.9.9/独立Node24.21.0，两个闲置WhatsApp停用并保留数据，官方插件及延期迁移已收尾。两个千问模型QA和图片权限验收通过；GPT真实应答仍被升级前已存在的本地代理依赖中断阻塞。最新事实及恢复边界见[当天生产记录](operations/2026/2026-10-14.md#生产升级结果已切换gpt真实应答待代理恢复)，不再把候选准备状态当作当前生产状态。

## 升级候选与切换范围

官方npm latest和GitHub稳定版均为2026.10.3。停用闲置WhatsApp后继续核对发现，现有微信2.4.8依赖10.3退休的四个SDK接口；腾讯最新2.4.10已移除其中三个，仍引用channel-message。官方npm包172518字节，sha512完整性及sha1均通过，包SHA-256为69dd18af16a992edbe3700d244f9591ab52f5f58abfe976a9f1250bd8eacdbbb。10.3没有相应export或通配导出，故当前微信链明确NO-GO，不能把关闭微信后的Gateway健康作为兼容通过。依据[上游同类问题](https://github.com/openclaw/openclaw/issues/166404)及本次真实包核对，本次仍选择已实测兼容的稳定版2026.9.9。

两个候选均要求Node24.16以上的24系或26.1以上，因此侧装独立Node24.21.0，不替换视频应用使用的node/current。上游微信发布兼容包后，再独立验证最新稳定版；不修改npm dist或维护退休SDK补丁。版本来源见[官方固定版本发布](https://github.com/openclaw/openclaw/releases/tag/v2026.10.3)及[升级说明](https://docs.openclaw.ai/install/updating)。

候选位于H1受管OpenClaw runtime release目录。官方Feishu及八个现有官方外部插件候选固定为2026.9.9；微信2.4.8及三个自定义业务插件沿用已验证实现。WhatsApp0.1.17在原9.9兼容验收通过，但因没有使用记录，追加隔离停用验收后拟在正式升级时禁用插件及渠道，保留安装、账户配置和历史状态，不因升级擅自换业务模型、降低思考强度或开放权限。

2026.9.9的四个配置副本均通过插件实际装载、post-upgrade Doctor、官方副本迁移和Gateway启动；历史会话读取分别为19、7、2、1。共享库迁移15→19，agent库19→24，9库完整性通过，转写事件条数保持。旧计划ID全部保留；新版自动生成的技能审查需要单独控制。新增受管CLI入口绑定独立Node，保留真实上游package.json位置，方便现有SDK身份发现；不修改npm dist。公开Gateway SDK在现有Node22及独立Node24中均成功导入，这只证明导入兼容，不替代实际RPC和生产关键链验收。

通过SQLite只读在线备份建立9个核心数据库逐库WAL一致的演练快照并校验；跨库的当次生产恢复点须停服后重新取得。真实迁移范围为四个profile各自的state/openclaw.sqlite，以及gpt-main/main、qwen-current/second-original与main、qwen-weixin-new/main、image-studio/image-studio五个agent数据库。会话正文、配置凭据和数据库均留在权限受控的节点目录，不进入Git。

隔离副本会携带源进程的运行租约。官方snapshot租约清理只用于已核验独立物理身份的演练副本；不得清除生产租约，也不得把副本维护阻塞当作理由停止生产。原始恢复快照保持不变。

生产升级需要官方前向数据迁移，不能只换回旧npm包回退。切换应先核验活动执行和当前身份，保存当次新鲜配置、启动绑定与数据库恢复点，逐个入口切换并验证历史数据、有效工具、通道及关键业务。需要回退时停止本次新实例，使用同一恢复点恢复数据库、配置与旧运行绑定。共享运行合同必须在正式切换时同步，避免后续部署继续要求2026.9.2。

截至本报告候选准备阶段，生产仍为2026.9.2，尚未修改生产数据库、主CLI指针或四个Gateway启动绑定。最终迁移和部署验收结果接续当天运维记录，不由本方案推断完成。

本次候选采用统一官方配置：skills.workshop.autonomous.mode=off、approvalPolicy=pending，关闭新版默认自动技能审查及自动批准，保留手动能力和用户计划。使用ops/openclaw/runtime-upgrade-policy.json同一声明，正式应用仍属于待确认的生产配置范围。10.3副本的数据库已迁移至20/24，部分Gateway与图片工具读取通过；微信SDK仍不兼容，因此整个四入口升级不接受10.3。所有临时Gateway收尾关闭，侧装与失败证据继续受控保留，不能报告为生产升级或全部候选已清理。
