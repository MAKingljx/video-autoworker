# 可维护架构与快速发布规范

Video AutoWorker 继续采用单仓库、模块化单体和单一任务链。OpenClaw 只承担身份、会话与入口能力；作品、任务、证据、审核、提炼、调度和发布状态由 Video AutoWorker 的应用服务与权威数据库维护。接入其他聊天或智能体平台时，只实现平台适配器，不复制业务状态机、数据库、审核逻辑或任务队列。

## 模块边界

| 模块 | 职责 | 权威状态 |
| --- | --- | --- |
| 平台适配 | 把平台身份、消息、查询、候选新增、审核和取消转换为稳定应用请求 | OpenClaw 或其他平台只提供身份与会话；业务状态不落在适配器内 |
| 导演脑应用 | 查询作品、提交候选、审核批次、提炼分段与进度投影 | Mission Control SQLite |
| 视频任务 | 接单、租约、分析、证据投影和结果查询 | Mission Control SQLite 与既有 n8n 工作流 |
| 发布操作 | plan、apply、status、cancel、resume、doctor、prewarm | router-state、intake revision、安装收据和追加式操作日志 |
| 运行控制 | 蓝绿槽位、连接排空、退役证明、路由切换和回滚 | 蓝绿状态文件、运行证明和受管进程身份 |
| 运维治理 | 传输清单、恢复资产、耗时与资源采样、最新事实和脱敏审计 | 只读清单与收据；不建立第二套业务状态 |

## 发布流程

1. `plan` 固定源码提交、组件差异、制品、目标槽位、入口 revision、动作和完成条件。确定性源码、制品、真实参数、安装器和目标槽位检查全部在暂停接单前完成。
2. `apply` 使用一个 operation ID 和一个受管取消信号。制品复制边界执行完整审计；同一物理制品后续只核对封存证据和文件身份，发生漂移时失败关闭。
3. 应用退役、绑定、启动、探测、切换与验收在同一个受管进程和同一把发布锁下执行。路由 generation 写入后即视为 `route_committed`，最终证明完成后才视为 `acceptance_verified`，入口和工作进程恢复后才视为 operation 完成。
4. `cancel` 只终止当前 operation 拥有的进程组。提交前停止后续动作；提交后先读取实际路由再决定验收或既有回滚，不以父进程返回值推测路由事实。
5. `resume` 只复用具有持久收据且能从权威状态重读的步骤。路由已提交时重新验收并恢复本 operation 拥有的入口和工作进程；身份不明或 revision 漂移时停止并要求重新生成计划。
6. 验收默认只覆盖改动组件、依赖闭包和真实合同。完整套件只在共享协议、数据库核心结构、认证边界、构建链或显式全量门禁变化时运行。

### 维护替换模式

允许短时中断时，新版先在接单外完成源码固定、依赖安装、构建、制品审计和恢复点校验。进入部署窗口后，发布操作必须先暂停接单、确认活动任务为零、完成权威数据库备份，并核对旧服务的路由、调度、PID、端口、数据库和静默状态；随后可以直接停止旧服务、启动新版、验证本次改动及其依赖闭包，再恢复工作进程和接单。

维护替换模式通过统一发布入口显式设置 `AIWORKER_BG_AUTHORIZED_LEGACY_STOP=1`，只跳过当前活动版本的导演脑投影链源码兼容复核，不跳过排空、调度、路由、运行身份、数据库、停止确认或新版验收。失败时保持接单暂停，使用 Git 固定版本、安装收据和已验证数据库备份恢复；每个恢复对象继续只保留两个有效历史版本。普通在线热切换不设置该参数，仍执行完整兼容复核；不得脱离统一发布操作手工启用该参数。

服务管理器不再用固定10秒判断应用启动失败。`AIWORKER_BG_STARTUP_WAIT_SECONDS` 默认90秒，可在10至3600秒内按节点性能调整；健康状态一旦成立立即返回，不额外等待。该等待只约束进程启动验收，不给业务分析、模型调用或导演脑提炼设置30秒总时限。

## 数据与恢复

运行配置和数据库路径位于权限受控的平台环境文件，独立于 Git checkout 和不可变 release。受管 active/drain 槽位缺少显式数据目录、数据库或令牌路径时必须拒绝启动，禁止创建 checkout 内的替代数据库。

代码回退使用不可变 release 切换；配置恢复使用对应安装器的精确备份；数据恢复只使用批准的恢复或补偿流程。每个恢复对象在当前副本之外最多保留最近两个已验证历史版本，活动版本、依赖供体和唯一恢复点不能进入删除候选。RPO、RTO、资源预算和预热性能目标在获得实测样本与业务决策前保持未设置。

## 长任务和审核

导演脑阶段输入只携带稳定引用和当前阶段所需摘要。大输入按时间线或章节生成有序分段，每段受独立大小边界约束并持久 checkpoint；全部分段完成后才合并和投影。聊天审核批次固定候选集合、版本、作用域和请求幂等键，逐条保存完成或未知结果；重启后从远端回读未知项，不因重复消息重复批准。用户口述的新内容保存为新候选，不自动批准。

进度只依据已持久完成阶段、分段 checkpoint、租约心跳和审核状态生成，同时返回 `progressKnown`、`lastProgressAt`、`heartbeatAt`、`blockedOn`、`lastErrorCode` 与 `nextAction`。排队、处理中、等待人工审核、冲突和完成必须明确区分。

## 运维证据

操作日志只记录 operation、phase、状态、错误代码、可重试性、效果状态、耗时、字节和资源样本，不记录 Token、密钥、消息正文、数据库行或原始响应。规则、故障和运行结论按 subject、revision、observedAt 与 evidence digest 保存；只选择最新且 revision 唯一的事实，历史记录不能自动覆盖当前现场。
