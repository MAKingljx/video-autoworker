# 视频封面严格阶段工具修复（候选）

## 触发原因

真实 qwen-current 会话中，旧的统一封面工具把四个阶段放在同一个仅要求 `action` 的 Schema 中。模型可合法发出仅含 `action=submit_protected_cover` 的调用，缺少工作流编号、帧引用和保护方案；请求在图片队列前被拒绝，因此没有真实图片任务。旧的泛化错误码也会把该参数问题显示为工作流不可用。

## 候选变更

- 保持一个应用工作流、同一会话/图片 scope 状态机及既有图片队列。
- 模型可见层改为四个 direct-only 严格动作：读取目录、取得候选帧、提交原片保护封面、查询图片任务。每个动作的实际输入字段均为 Schema 必填，不使用 `oneOf` 或仅凭说明文字表达条件必填。
- 旧 `aiworker_video_cover_workflow` 连同更早的帧工具进入退役清单，不保留为模型可见的并行入口。
- 封面失败的图片回执会替换下一条模型最终回复，避免把内部处理计划发给用户；参数缺失明确为 `VIDEO_COVER_WORKFLOW_REQUEST_INVALID`。
- 随后的真实提交还发现候选帧收据漏写视频名，导致已取得的帧在提交时被状态机判为无效。该字段已改为由受控工作流响应显式写入，不能再依赖候选帧传输对象。另将主标题框过小这一服务端保护校验映射为可修正的工作流错误，避免再泛化为服务不可用；对应插件修订升级为 `0.5.5`。
- 运行收据把图片能力的来源提交绑定到当前控制/插件提交，而非未变化的应用 release，允许安全记录插件独立升级。

## 候选验证

- 图片插件 Node 定向套件通过，覆盖严格参数、阶段状态、一次提交和失败用户回复。
- 图片能力合同、工作区指引、运行收据绑定和 Python 图片安装器定向检查通过。
- 本文件仅记录本地候选；H1 安装、真实对话验收和用户已授权的一次新图片提交另行追加。

## 一次受控候选执行

- 用户授权后，qwen-current 经严格工具实际创建了唯一图片任务；早先的帧引用和两次未建任务回执均未被当成任务重试。
- 该任务在原片保护文字层终止，错误为 `protected_text_line_selection_missing`，没有成品图、采用或发布。只读复核显示模型两次把主标题中的“又”分别漏写和误写为“叉”；严格 OCR 拒绝是预期保护行为，不是队列或封面工作流不可用。
- 该任务未自动重试、取消或改写；后续若要再次出图，必须在新的系统版本验收后由用户重新确认一次候选生成。

## 0.5.6 候选：任务凭证、受理恢复与文字保真

- 新增独立的会话级图片任务凭证库。仅已成功返回的任务编号可进行状态、读取、检查或取消；未知编号在插件层失败关闭，且不访问图片服务。提醒订阅仍只负责投递，不兼任授权。
- 新增视频封面单帧提交尝试账本。受理不确定时固化原始计划并以同一幂等键恢复；标题框被明确拒绝且未建任务时最多允许一次修订；已确认任务只返回同一任务状态。
- 长中文单行字在 OCR 不匹配时扩展为最多四个可审计的本地模型候选。第一个保持作业种子，后续候选使用确定性派生种子和逐字保真提示；每个素材收据绑定实际种子，旧收据继续按原作业种子验证。
- 本节仍是本地候选，尚未部署到 H1，也没有因此创建第二条图片任务。

## 升级预检兼容修复

- H1 的旧图片服务健康接口与应用内数据库完整性均正常，但升级器使用 `Path.as_uri()` 形成的三斜杠 SQLite 只读 URI 时，macOS 自带 SQLite 无法重新打开该私有数据库；因此预检安全拒绝，没有发生停服、备份或配置替换。
- 升级器改为从已经过路径校验的绝对文件路径生成并转义可移植的只读 URI；定向安装测试覆盖含空格路径和真实只读汇总。该修复只影响升级前的数据库只读核验与备份源连接，不改变任务数据库、图片服务 API 或历史结果。
