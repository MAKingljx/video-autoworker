## 0.3 单入口重构（本地候选）

- 进入 `0.3.0` 开发前的生产只读预检已补齐 `0.2.0` 过渡证据：installed package、live runtime、OpenClaw 安装索引和 qwen-current 配置四处均为 `0.2.0`，runtime 正常加载三个旧 hook 和一个可选工具，索引仍是 canonical path source，目标 agent 仍是已知的 `profile=full` 加限制性 allow 变换。该证据只确定 `0.3.0` 的真实升级起点，不证明新 `before_dispatch` 或自然语言入口已经验收。
- 两次 CLI 自然语言尝试均安全地零提交，但也证明 `--local` 不经过真实 Telegram 的 `before_dispatch`，不能作为该入口的生产验收。为消除模型选工具、host runContext 和 CLI/Telegram 上下文差异，`0.3.0` 候选删除 `aiworker_analyze_video`、prompt/tool hooks 及其大型运行状态机，只保留一个原生 `before_dispatch`。
- 这个 hook 在模型前统一分类精确命令和肯定自然语言。有效请求校验唯一绝对路径、Telegram 私聊、一致身份及配置中的 owner sender 哈希后，只调用共享 runner 一次；随后立即返回人类化任务编号，不等待 n8n、不查询状态、不重试、不回投结果。目标 Telegram 私聊中的视频说明、能力、否定、条件和示例也由同一 hook 直接短答，零模型、零工具、零任务；真正无关的私聊才进入千问。群聊和其他渠道不属于这项结构性保证，也不能通过该插件提交视频。
- “不要等待、不要盯着、不要回投、不要回复结果”是异步交互偏好，不取消执行；“不要执行、不要提交、先别分析”才取消本次派发。“只分析/仅分析这个视频”仍是肯定的完整音画请求，不得当作否定；“只分析画面/仅分析音频”等局部模态当前不受支持，必须短拒绝而不能误提交。视频号、视频会议、视频编码等普通复合词不被当作媒体请求。缺路径、多路径、URL、相对路径、控制字符和不支持格式全部短拒绝，不猜路径、不搜索文件、不进入 generic task。
- runner 固定使用 `delivery=none`、`wait-seconds=0` 和 `--no-trigger-recovery`。若触发请求在受理边界断开，客户端以专用退出码将结果标为“提交状态暂未确认”，并保留同一稳定任务号供以后查询；本轮仍不读取状态或再次提交。新任务只接受 `accepted/duplicate=false`，幂等任务只接受允许的既有状态，失败或未知状态不得显示为已提交。
- fresh install 与受控 `0.2.0 -> 0.3.0` upgrade 共用 hook-only、sender-hash、Telegram DM policy、唯一 binding、备份、锁、官方 force-install、live runtime 和回滚门。升级恢复完整 pre-0.2 agent tools 对象，不残留 0.2 可选工具权限；只允许刷新 `qwen-current`，不得触碰 3017、n8n 或其他 profile。技能和插件的有变化安装都先完整验证新恢复点，之后才精确移除未受保护的最旧 verified 备份，把各自家族收敛到最多两份；失败和回滚不清理既有恢复点。
