# 视频学习恢复与发布队列核对

10月27日的发布在共享组件安装前被队列安全检查拒绝，原应用和路由未切换。排查确认，持久队列中有一个实际待交接的视频；检查同时将该视频的备份及另一批次的历史备份计入活动交接。此前维护持有的接单暂停和视频队列停止在会话中断后未及时恢复。

10月28日按本操作保存的暂停版本、原因、受管服务身份及配置摘要核验后，恢复原视频队列并以 CAS 恢复接单。待处理视频以原任务编号和原暂存文件继续，未重新复制素材；历史全部需要关注的批次保持原状态，没有自动重新学习。原应用继续提供服务，独立 Worker 的已验收版本保持运行，五秒学习窗口和模型设置未变。

后续按用户要求等待当前视频完成，再发布此前已验证的学习修复制品。针对维护阻断，在本地处理权威主文件与备份计数、等待交接时暂停前延期及竞态下的所属资源恢复。备份仍参与完整性和冻结证据，真实素材交接仍受原安全门保护；这些改动在完成测试、提交和生产验收前只属于本地候选。

候选队列扫描器已对生产队列进行一次只读检查：识别出1个真实运行中的队列项、1份主交接记录、2份备份交接记录和1个保留为 attention 的历史批次，65份状态文件均进入快照。检查没有更改队列或素材；在途交接仍会使候选发布流程延期。历史有效的仅主文件状态和不同阶段的备份均保留，不制造或清理备份。

当前生产运行收据核验为 `drift/runtime_receipt_unverifiable`；只读诊断为收据引用的 Worker 与当前已切换 Worker 不一致。接单和现有学习任务已恢复，但不能把运行收据称为已对齐；待当前任务结束并完成正式发布验收后，由现有发布控制器原子更新并核对唯一运行收据。

队列投影与共享安全检查定向验证24项通过，发布控制器及中断恢复验证87项通过，类型、相关静态检查和源码敏感信息检查通过。维护前活动依据只保存私有摘要并绑定原计划与操作日志；续作仅复用原依据，遇缺失、篡改、身份变化或状态漂移保持失败关闭。远端以只读方式验证候选活动采样，覆盖1068项和13处已知SDK引用，耗时61毫秒；没有写入生产。独立 Worker 的80项源码闭包摘要仍与已运行制品一致，后续无需因控制器更新重新构建或重启该 Worker。

远端 CI 发现共享安装检查的两处旧测试与已经迁入共享 Git 布局模块的实现不一致：已补全测试夹具依赖，并验证共享检查对干净、已修改、已暂存和未跟踪源码的实际行为；该测试文件43项通过。此次只修正测试与说明，不放宽生产检查。

后续 CI 中上述真实 Git 测试在共享 macOS runner 上耗时略超默认5秒而超时，其余169项通过；已仅为该测试配置20秒预算并验证通过，不调整视频或模型任务的运行时限。

用户随后授权结束当前第8个视频，并要求完善单条停止接口。只读检查发现旧版没有能同步结束后台媒体执行的单条停止接口；未手改任务状态或结束共享模型服务。该视频随后自然成功：父任务和四个媒体子任务均首次尝试成功，音频、画面和摘要各210段、索引连续，原素材身份不变；没有重新学习。结构检查不代表逐段事实内容已经人工审核。

单条停止能力正在本地开发和隔离验证，包含持久停止意图、执行权与晚到写入围栏、受控子进程、模型请求安全收尾及保留已完成结果。旧版在途闭包不能凭新接口假称已经停止；生产发布须在安全条件成立并完成迁移及受影响 Worker 验收后执行。

候选实现覆盖受理前的排队和素材暂存，以及受理后的单条停止：停止请求先持久登记，分别等待原队列所有者或媒体执行者确认实际写入收尾；模型请求状态无法确认时保留待核对，不将中断连接当作模型已退出。成功片段与原素材保持原有身份。暂停批次仅核对指定停止事项，控制不可确认不自动恢复派发；素材恢复清理与停止请求使用同一事务顺序保护。范围仅为视频任务，原有五秒窗口及模型配置不变。

本地以 Node 22 验证任务处理组件195项、媒体与数据库兼容相关108项，以及停止领域、路由、数据竞争和接口合同100项；通过接口一致性与源码敏感信息检查。以上为本地及隔离证据，未代表生产已生效。新增061数据库能力要求重新构建 Web 与独立 Scheduler Worker，并更新实际受影响的 TaskFlow；部署使用当时状态新建的计划，不复用绑定旧接单版本的计划，完成后应以真实进程、任务与唯一运行收据复验。
