- 请求和远端返回均拒绝所有 HTTP/HTTPS URL，防止飞书资源链接或普通外链绕过资源边界。
- 全片摘要只绑定覆盖完整媒体时长的全局证据；局部时间段只使用同段结构化视觉观察，不能把全片结论重复绑定到局部时间码。已有 `materialId` 原样复用；没有时按文件内容生成稳定 ID，随机收件箱 `videoKey` 不再冒充长期素材身份。

## 新任务入口暂停与蓝绿发布安全候选

- 全局准入闸门只阻止新的顶层任务；已存在的同幂等任务、状态查询、n8n execution、模型节点、媒体节点和最终回调继续运行。暂停与新任务创建在同一个 SQLite `IMMEDIATE` 事务内线性化，管理写入使用 revision CAS 并保留原因和操作者审计；非全局发布管理员只能看到最小接收状态。
- 3017 改为稳定 loopback router 加 blue/green 不可变槽。新任务持久绑定 `runtimeSlot`、`runtimeReleaseId` 与三个 callback URL；claim、node、media 回调都校验父任务的 release affinity。迁移 `053` 至 `056` 分别提供 scheduler 单主、webhook 派发租约、子执行 lease/fencing 与父 execution owner，响应丢失时只允许同一 execution 续接，不同 execution 判重终止。
- 正常切换和自动回滚在 router generation 更新后先有界等待目标槽观察精确 generation 并成为 scheduler leader，再执行 readiness、页面与 API 验证。旧槽退役先冻结新 callback、保持 listener 存活并再次等待 release-owned callback、lease、连接和静默窗全部归零；等待失败会解冻并保留旧进程，不能先停服务再发现仍有任务。legacy `/api/n8n/execute` 只允许显式 `legacy-v1` 且非 slot runtime，只有 `reviewer` 节点可完成父任务。
- 新增统一运行错误投影：公开响应和任务持久化只保存固定错误码与安全摘要；模型 HTTP、OpenClaw、ffmpeg、n8n callback、router 以及素材 API 的原始诊断只进入受控日志并先脱敏 URL、路径、凭据、内部 ID 与高熵值。
- 本地候选新增 blue/green runtime attestation：slot 启动使用 `umask 077`，统一拒绝符号链接、非当前用户所有或组/其他用户可写的三个环境文件；已有 PID 仍存活时拒绝覆盖。启动器以 `0600` 和 fsync + rename 原子记录 PID、slot、role、release、manifest、loopback endpoint、canonical SQLite 路径与 canonical router state 路径，证明中不包含凭据；同一路径同时导出给 scheduler 交接逻辑。
- `probe` 命令仍可验收连接隔离快照的 probe 进程；`switch` 与 `rollback` 则强制目标 role 为 `active`，并要求 runtime attestation、binding、PID、cwd、release 清单及 router state 路径完全一致，同时与显式 `AIWORKER_BG_LIVE_DB_PATH` 的物理规范路径相同。probe、drain、错误数据库或错误 router state 的进程都会在写 router state 前失败关闭。
- OpenClaw `aiworker-video-command` 候选版本由 `0.5.12` 提升为 `0.5.13`；唯一安装器明确允许从生产既有 `0.5.12` 进入该版本，不再把源码已变化但版本相同的载荷误判为“已安装”。task-flow 不新增或虚构独立版本。
- 当前旧生产 release 没有 callback affinity，所以首次迁入蓝绿结构仍必须完整归零一次。首次引导成功后，常规 3017 发版只需先暂停新准入，即可在旧任务继续执行时构建、验收和切换新 release；旧 release 按自身 affinity 继续收回调，只有退役旧槽需要等待它自己的任务与连接排空，不再把全局 n8n 活跃 execution 归零作为切换前提。
- 本地兼容性复核发现首次引导还有一个必要前置：旧生产工作流与 `slot-v1` strict callback schema 不兼容。旧通用工作流没有父任务 claim，旧视频工作流的 claim/media callback 没有 `executionOwner`。候选新增只读验证器，固定核对两条工作流的 active/published version、发布内容摘要、execution-owner 协议以及真实 n8n PID/SQLite 绑定；旧工作流、停用、内容漂移和错绑都失败关闭。
- 进一步按 n8n `2.31.6` 实际实现核对：`import:workflow` 会丢弃 JSON 的 source versionId 并生成新 UUID，`publish:workflow` 再把 `activeVersionId` 指向该 history。验证器因此要求数据库 current/active/published version 相互一致，不错误要求等于仓库 source versionId；`settings` 使用 workflow entity 的 simple-json，published `nodes/connections/nodeGroups` 使用 workflow history，缺省 nodeGroups 规范为 `[]`。预期内容从基线 application release 对应的精确 Git commit 读取，同时要求受管 n8n runtime 的 `SOURCE_COMMIT` 和 release 内两条工作流与该 commit 一致，避免 checkout 前移或切换导致身份漂移。
