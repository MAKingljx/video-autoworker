## 实现范围

Next.js 默认不再启动后台调度，数据库启动仅核对既有 schema 和 WAL。独立 Worker 复用原 SQLite 租约、任务与提炼模块，通过同用户 Unix socket 提供状态、触发、排空和页面事件通知；Webhook 仍由原变更进程负责，中继通知不重复触发投递。首次交接以旧 Web 的 PID、数据库、路由、有效租约及作业归零证据准备 follower，切流后取得唯一领导权，再完成持久交接；经评估确需回滚时只处理本次准备的 Worker。

发布计划按已安装 Worker 的完整源码依赖清单、制品摘要、PID 和数据库身份判断复用。依赖未变且 Worker 健康的应用更新只短暂暂停新准入，不等待已有任务全局归零；执行器、插件或不兼容依赖更新仍使用对应维护流程。旧回调版本归属、目标槽位退役、路由 CAS、真实数据库身份和制品完整性继续核验。切流前后均核对计划绑定的 Worker，避免准备过程中被其他版本替换。

制品打包直接使用已经构建和审计的 standalone，保留权限与链接，记录实际 OS、架构、Node ABI、源码和内容摘要。CI 上传的是候选，晋级必须核对准确仓库、run、attempt、提交及最终 Quality Gate 成功；本地或生产等价构建需要独立明确的验证收据，不冒充 CI 通过。

健康接口区分进程存活、应用就绪和完整链路健康；失败子项正确汇总并返回503。磁盘使用率按数据库和显式素材路径所在卷批量采样，缺失值保持未知。浏览器测试按受影响文件和功能范围选择，直接修改测试必选，空清单不能当作通过。

导演脑摘要、判断依据与领域事实分责，不再用简介覆盖人物弧光或故事变化。已投影历史保持原始证据与人工审核状态；未投影 v1 经共享兼容声明规范化为当前结构，再走同一校验和投影链。旧语义污染字段标为未知；共享只读预检防止旧外部写入结果未知时重复创建。上线前只读核查未投影 v1 数为0，本轮无需转换生产候选。

数据库备份独立按每天03:30执行，设备恢复或失败后补跑，发布可按源变化取得一致性恢复点。同恢复对象的历史备份跨目录计入两份上限；旧 n8n 档案恢复时包含 WAL，淘汰前保留经校验的非数据库恢复资产。RPO目标为24小时，恢复耗时以真实隔离演练记录，不用推定值代替证据。
