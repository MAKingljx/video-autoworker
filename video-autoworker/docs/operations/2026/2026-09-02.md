## 3017 首迁桥可选 token 文件合同修复

- 生产只读 preflight 暴露出合同偏差：应用允许 token 使用文件在首次写入前不存在，读取缺失文件会按空记录处理；首迁桥却无条件要求该文件已经是 `0600` 普通文件，导致合法空状态在任何隔离探针启动前失败关闭。
- 候选将 token 状态收敛为单一安全快照。文件存在时继续要求当前用户所有、普通文件、非符号链接且权限为 `0600`，并绑定设备号和 inode；文件缺失时只允许数据库所在物理数据目录下的默认 `mission-control-tokens.json`，要求路径本身非符号链接、父目录归当前用户所有且不可由组或其他用户写入，并绑定父目录设备号和 inode。工具不会为通过检查而创建空 token 文件。
- preflight 在隔离探针前后重复比对 token 的存在性与身份；apply 在停止旧进程前、候选健康后和运行标记提交后再次比对。缺失后出现、文件替换、路径类型或权限变化都会失败关闭，避免检查与切换之间的 TOCTOU 漂移。
- 回滚采用刻意更窄的可用性例外：如果切换已经开始后 token 身份发生变化，候选不能提交成功，但自动恢复旧 3017 时只重新验证“当前状态仍满足安全合同”，不要求等于初始身份。这样可在安全文件由其他并发写入正常创建时优先恢复服务；若当前状态是符号链接、错误权限、错误所有者或危险父目录，回滚仍失败关闭并报告严重错误。
- 开发和验证仅在从 `origin/main` 建立的独立临时 worktree 进行，未读取 token 内容、未创建生产 token 文件，也未连接、停止、重启或修改生产 3017、n8n、Gateway、模型、任务和数据库。定向测试覆盖合法缺失、错误默认路径、危险父目录、悬空符号链接、现有文件权限、缺失后出现、切换边界复核及回滚可用性取舍。
