## 需求与决策

用户希望把飞书作为 Video AutoWorker 的“导演脑”云脑，长期积累素材理解、人物认知、故事发现、素材价值判断、叙事方案、导演案例和技能技法。

导演脑使用项目测试飞书账号构建独立应用和独立数据空间，与现有飞书工作大脑隔离；但它仍属于 `PROJ-VIDEO-AUTOWORKER`，不是新的逻辑项目。已有 task、batch、material、scene 和 shot ID 原样复用，不能因为迁移到飞书而再次生成来源身份。

现有飞书工作大脑继续保存项目规则、决策、计划和任务；导演脑保存纪录片领域知识与导演判断。两者物理隔离，但导演脑未来只能作为现有唯一视频任务链的长期知识与决策子系统，不能维护任务状态机、队列、重试、取消、重提或媒体处理副作用。

飞书只保存结构化知识、来源 ID、证据时间码、版本和置信度。原始视频、逐帧图片、完整原始转写、向量、日志、数据库、任务状态和凭据继续留在受控本地系统。自动内容必须先进入候选或待审核状态；高层判断必须回链到素材证据和导演意图版本。

以上验证证明独立飞书应用、schema v2 十一表、作品级隔离、审核状态机、受信证据写入和六层知识闭环真实可用，不只是浏览器页面或静态 schema 存在。验收使用的是隔离测试作品，不证明远端正式任务已自动同步，也不证明人物、故事、判断或脚本生成已经在真实业务规模稳定运行。

OpenClaw 直接工具路径已完成 7 动作的契约与调用验证。一次全新的本机自然语言会话使用作品名或别名、不提供内部 ID 完成六层查询：整个运行只调用导演脑工具 `1` 次，参数只有 `action=workflow` 与 `query`，没有 `workId`；最终答案逐字采用受控响应契约的用户可见结果，不暴露内部 ID，不用模型补造领域事实。该结论只覆盖本机隔离环境；具体会话标识不进入 Git。

## 安全检查

- App Secret 只存放在独立 Keychain 项中，没有写入代码、schema、文档或 Git。
- 本地资源目录保存在仓库外，并使用受控文件权限。
- schema 主动拒绝名称包含 secret、token、password、密码、密钥或私钥的字段。
- 记录写入主动扫描私钥、常见 API Key 和 secret 赋值模式。
- `.PhoenixBrain`、本地资源目录、凭据、临时 API 记录和远端资源内部 ID 均不进入提交。
- standalone 构建会在完成后枚举实际成员；发现 `.PhoenixBrain`、`.git`、任意大小写及扩展形式的 `.env*`、常见包管理凭据文件、私钥文件或本地 catalog 即失败，不依赖 `.gitignore` 作为发布证明。
- 临时写检查带随机稳定 ID，并执行多轮清理及最终残留确认，没有留下测试数据。
- 一次性 Keychain 更新探针在确认无代码或配置引用后已精确删除并验证不存在；正式导演脑专用凭据项未改动。
