# 2026-09-19 Resolve 剪辑节点架构设计

用户要求完成远端 GPT / OpenClaw 操作 macOS DaVinci Resolve 的架构设计。本次完成架构设计和批次 A/B 的本地实现，未安装、修改生产配置、剪辑、渲染或部署。

通过新的 SSH 入口严格核对既有主机身份，确认默认远端 Mac 为 macOS 26.5.2 / arm64，Resolve 应用版本21.1.0（build21.1.00017）且存在运行进程。目标机器的官方 Scripting README 与类型文档可读。SSH Python 只读 scriptapp('Resolve') 返回空，Studio授权、Local设置、解释器和GUI会话仍待验证。gpt-main配置的默认模型是openai/gpt-6-astra；本次没有请求模型或读取用户工程正文。

设计采用同机独立 Resolve Executor，通过官方 Python API 操作任务时间线副本；GPT负责计划，业务状态、批准、幂等、恢复与结果索引由现有AI-worker单一应用服务管理。现有模型会话RuntimeProvider不充当剪辑执行接口，现有模型node-execute路由也不直接接收剪辑命令。新增设备能力需通过同一任务claim/finalize与取消合同。

架构文档明确素材身份、分段证据复用、计划修订、帧率与时间码、单实例互斥、结果未知对账、长渲染job归属、预览和文件验收、OpenClaw薄入口以及按组件发布。统一运行收据仍为后续实现目标，不把本次设计写成既有能力。社区MCP仅作候选参考，官方21.1的AI助手集成需按实际安装验证，不引入并行可写后端。

验证范围为源码合同、官方目标SDK说明、只读软件探测、EditPlan/Executor 定向测试、TypeScript、Python 语法和变更文件 ESLint。当前通过 Resolve edit-plan 4/4、fake-Resolve Executor 2/2、TypeScript、变更文件 ESLint 与 Python py_compile；没有运行无关测试、完整构建或生产写验收。设计见[Resolve剪辑节点架构](../../architecture/resolve-editing-node.md)。

本轮新增 src/lib/editing/edit-plan.ts、resolve-executor.ts 和 resolve-executor-protocol.ts：计划包含素材内容摘要、证据完整性、项目/时间线基线、帧率、左闭右开帧区间、能力需求和计划摘要；执行合同提供稳定 operationId、payload 摘要、能力/项目/时间线预检，以及“调用后响应丢失”返回 unknown 的边界。新增 ops/resolve/resolve_executor.py，可在 Resolve 本地 GUI 会话中只读探测、创建计划副本并按已提供的 Resolve MediaPool 唯一 ID 追加片段；缺少身份、工程或素材唯一 ID 时失败关闭。该执行器尚未接入 OpenClaw 或生产任务入口。
