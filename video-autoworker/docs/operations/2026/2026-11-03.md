# Ollama 服务管理器冲突清理（2026-11-03）

## 需求与发现

生产体检发现 `ai.aiworker.ollama`（LaunchAgent，`KeepAlive=true` + `RunAtLoad=true`，执行 `~/ai-worker/bin/ollama serve`）与 `Ollama.app` 争夺 `127.0.0.1:11434`：端口已被 App 的 server 占用，该 job 每次启动都 `bind: address already in use`，被 KeepAlive 无限重启，持续向 `~/ai-worker/logs/ollama.err.log` 写错误（清理前 83,381,115 字节、约 130 万条，且仍在增长）。

## 影响评估（执行前）

- 全机 `bin/`、`scripts/`、`~/.config` 内**没有任何引用** `ai.aiworker.ollama` 这个 label。
- `11434` 由 `Ollama.app` 提供，App 自带登录自启 label `com.ollama.ollama`（已加载），重启/登录后仍会起来。
- `~/ai-worker/bin/ollama` 是指向 App 内二进制的软链，CLI 能力不受影响。
- `~/.config/video-autoworker/model-routes.json` 中的 embedding/rerank 目标只依赖端口可用，不依赖由哪个进程提供。
- 结论：停用该 job 不会丢失服务；唯一风险是"若将来去掉 App 自启"，此时需重新启用一个管理器。

## 决策

保留 `Ollama.app` 作为 11434 的唯一管理器（A 方案），停用并退役 `ai.aiworker.ollama`。

## 实际变更

- `launchctl bootout gui/<uid>/ai.aiworker.ollama`。
- plist 退役（不删除）：`~/Library/LaunchAgents/ai.aiworker.ollama.plist` → `~/ai-worker/backups/launchagents-retired/2026-11-03/ai.aiworker.ollama.plist`。
- 日志归档并截断：`~/ai-worker/logs/ollama.err.log`（79MB）与 `ollama.log` → `~/ai-worker/logs/archive/*-2026-11-03.gz`，原文件归零。

## 验证

- `launchctl list` 不再出现 `ai.aiworker.ollama`；`com.ollama.ollama` 仍在。
- `127.0.0.1:11434` 仍由 App 的 server 监听；`/api/tags` 正常；`ollama list` 正常（nomic-embed-text、bge-m3、qwen3-reranker 等）。
- 30 秒后复检：错误日志保持 0 字节（不再增长）。
- 同机其他服务未受影响：3017、5678/5679、18091、18092、18094、18789、18889、18989、19289、18095 全部在听。

## 部署与回滚

- 无业务部署、无数据变更、无发布制品变更。
- 回滚方式：先把 `Ollama.app` 自启停掉（避免再次抢端口），再从 `~/ai-worker/backups/launchagents-retired/2026-11-03/ai.aiworker.ollama.plist` 恢复 plist 并 `launchctl bootstrap`。**不要两个管理器同时 `serve`。**

## 已知问题与下一步

- 当前 11434 的可用性依赖 `Ollama.app` 登录自启；若未来移除其自启，必须同步启用某一管理器。
- 建议把"11434 是否有且仅有一个管理器"纳入只读巡检项（例如 doctor 或体检脚本）。
