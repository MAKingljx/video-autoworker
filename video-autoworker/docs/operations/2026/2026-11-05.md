## 问题与边界

2026-11-04 的跨午夜飞书会话反复以不完整参数调用旧图片工具。通用导演脑投影掩盖了图片错误和任务回执，模型无法识别无进展而循环调用；同一时期流式卡片关闭导致无效更新日志。

本次只调整 OpenClaw 图片适配、会话压缩和飞书投递配置。图片应用继续是唯一队列、幂等、取消、媒体与模型调用权威；没有新增图片任务、改写候选、处理视频学习任务或改变模型路由。

## 学习视频封面的原片候选帧链

### 选择职责

此前封面流程由任务方先从真实原片提取少量候选帧，再把图片发给 OpenClaw；OpenClaw 自己选择最终画面、撰写文案和提示词。问题出在候选帧依赖手工准备，学习任务成功后会清理临时抽帧，已学习片段工具只返回摘要，因此第二个入口不能自行看到原片画面。这不代表需要让 Codex 代替模型选镜头。

本地实现沿用同一分工并自动化候选准备：OpenClaw 先读取已完成学习的片段摘要，自主选一个片段编号；应用通过唯一视频源索引回到同一个任务的原片，仅抽取该 5 秒片段 20%、50%、80% 位置的三帧；OpenClaw 收到摘要、三个原生图片块和短期帧引用后自行选择最终帧，再调用原片保护封面工具。原片路径和任务 ID 不发送给模型，图像仍走已有图片应用与唯一队列。

### 安全与验证

新增受控回环 API 只接受精确视频文件名和一个片段编号；必须匹配唯一成功的学习任务、已成功片段和同名源素材，并核验原片在抽帧期间身份不变。仅支持本机文件协议的 FFmpeg、限制候选帧尺寸和数量、请求取消会终止当前抽帧子进程。OpenClaw 侧引用位于 qwen-current 私有媒体目录，权限 0700/0600、SHA-256 校验、会话和 profile 范围绑定、60 分钟过期；image-studio 不获新工具。选定帧仍通过现有原片保护模式与原任务队列，不自动采用或发布。
