# 2026-08-13 AI-worker 0.5 Qwen 视频调度本地候选

## 结论

本轮在本地候选工作树收敛 `0.5` 视频调度契约：`second-original` 的原生
`before_dispatch` handler 内部调用宿主 Qwen 一次做无工具结构化语义分类，宿主
继续掌握私聊鉴权、原消息证据、稳定身份和所有副作用。单视频与目录统一进入持久化
全局串行 video lane；状态仅接受当前消息中的完整显式 taskId 或 batchId 并只读一次。

该结论不代表 GitHub main、安装包或生产环境已经更新。本轮不执行 Git 操作、安装、
部署、远端写入、服务重启或生产验收。

## 需求与决策

- 分类动作限定为单视频派发、目录派发、task 状态、batch 状态、无副作用短答和
  无关聊天放行。classifier 不使用工具，也不能访问文件。
- Qwen 分类不是授权。宿主必须验证授权 Telegram 私聊、`second-original` 会话与
  发送者一致性，并从当前原始消息独立提取唯一绝对路径或完整显式 ID。
- 不再沿用 `0.4.1` 的纯正则状态入口，也不保存或推断 implicit recent task。
- 单视频作为一个 item 的持久任务，与目录批次共享进程级全局锁；跨任务也必须严格
  一次只运行一个视频。
- 派发只入队并返回 handled 短回执，同轮不查询、不轮询、不等待、不重试、不重提，
  完成后不自动回投。
- classifier、鉴权、证据、输入和 runner 任一失败都由 handler catch 并 handled
  fail-closed；只有真正无关的 `pass` 进入普通 Qwen。
