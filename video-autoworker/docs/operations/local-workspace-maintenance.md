# 本地工作区维护

AI-worker 根目录是同一 `PROJ-VIDEO-AUTOWORKER` 的飞书管理根；Video AutoWorker 产品 Git 仓库位于其 `video-autoworker/` 子目录。正式产品目录使用项目名称，内部 `src/` 放业务源码；回滚目录独立放在工作区的 rollback 子目录。日常只使用一个实际产品目录，不能为了整理目录复制出第二份长期源码。

本机从产品子目录读取飞书时，显式将 AI-worker 管理根传给 resolve。主 `.PhoenixBrain` 位于管理根、权限 0600；根的运行资产不整体入 Git。飞书档案变更先准确回读，再迁移源标记并验证根绑定。其他设备必须核实自身真实根和仓库身份。

## 目录与生命周期

| 类别 | 维护方式 |
|---|---|
| 当前产品源码 | 通过 canonical Git 管理源码、工作流、部署脚本、测试、模板和脱敏记录 |
| 运维说明 | 工作区根 README 提供入口；设备、长期决策、每日事实分别维护 |
| 生成结果 | 统一进入工作区 `output/` 的任务或日期子目录 |
| 私有证据与恢复资料 | 存放在受控 `private/`；不提交、不作为普通缓存清理 |
| 历史工作树 | 当前副本外，同一恢复对象最多两份已校验、可恢复版本；独有修改或运行数据待处理项明确列明解除条件 |
| 临时工作树 | 建立时记录用途，任务结束后检查引用、提交与数据再决定移除 |

目录叫 `tmp` 不代表内容可删除。中央 Git 目录可能被多个工作树共享，必须先核对 `git worktree list --porcelain`。完整项目还包含配置、测试和部署脚本，不能把整个仓库误命名为 src。移动主 Git 存储时，按 Git 官方 worktree repair 流程修复链接；读取工作脑时使用迁移后的准确项目根，保留源 `.PhoenixBrain`。

共享Git可以使用工作区 `repositories/video-autoworker.git/` 这一bare存储，仅挂接当前产品和两份回滚，不保留中央旧源码工作副本。移动原common Git之前保全差异、数据、refs和可恢复历史；使用官方worktree repair，逐树核对gitdir、common-dir、HEAD、status及bare属性。全部通过后才能删除原旧源码，失败时移动原Git库回原位并repair恢复。不得通过重新clone后覆盖现有Git链接来迁移。

独有旧方案保存差异和原base，离线数据独立保全；不为保存几个修改保留整棵长期源码。历史Git对象和独立上游实验Git可以保留为受控历史资产，不作为运行入口。清理普通截图/日志时明确它们属于可重建测试输出，不在验收记录中声称仍保留原图。

## 清理顺序

1. 明确本机范围，核对当前源码、Git 状态、工作树关系、进程 cwd、打开文件、命令参数和启动配置引用。
2. 对未提交、未跟踪源码及需要退役的历史入口生成私有清单和备份，逐成员校验；最终归档不得包含任意层级的 `.PhoenixBrain`。
3. 缓存只选取经过核验的准确路径。当前开发依赖、运行服务、有效回滚制品、数据库、配置、索引和模型不纳入普通缓存删除。执行前重新核对路径类型、归属、引用及受保护内容，状态变化即跳过。
4. 失效 worktree 登记通过 Git 处理，保留仍存在的源目录。任何可能失去引用的提交先建立持久引用和可恢复的 Git bundle，再清理登记；不同时执行 Git 对象回收。
5. 核验保留数据和独有源码的字节、Git 状态、入口解析与备份恢复条件，再记录实际删除、迁移、保留原因及空间变化。

执行 `VAW-WORKSPACE-GOVERNANCE-001` 和全局 `RULE-BACKUP-RETENTION-001`：备份集按恢复对象定义，跨目录和压缩包统计，不得靠改名或合并包隐藏超额版本。新备份先验证完整性与恢复条件，再清理超额旧备份。Git 提交历史不截断，源数据库、素材、记忆和唯一恢复点不能为凑两份删除。仍有未处理历史目录时必须说明实际状态，不能只检查 rollback 目录就报告全项目清理完成。

`node_modules`、`.next`、Rust `target` 通常可以重建，但目录里可能混入配置或数据，不能仅凭名称删除。历史可执行入口退役时，应保全源码并移出日常工具发现路径，不能用归档的旧入口再建立第二条业务链。

## 验证与恢复

本地清理不等于生产部署，不停止或重启生产服务。未改动业务源码与当前依赖时，验证重点是文件完整性、Git 关系、入口和恢复资料，无需重跑无关业务全量测试。

空间结果注明统计口径：目录占用减少、文件逻辑大小和磁盘可用空间不是同一个指标；硬链接、APFS 克隆及其他进程写入都可能使它们不同。

恢复历史文件时，先解包到隔离目录，对照清单和现有文件进行选择性恢复。缓存按对应锁文件重新安装、构建；不承诺恢复旧缓存的原始字节。清理不设置自动周期，后续仍按任务核验。
